# Ark macOS 原生应用

[English](README.md) | 中文

Ark 的原生 macOS 应用。AppKit 管理进程与窗口生命周期，SwiftUI 绘制应用控件；在系统分配的 `127.0.0.1` 端口上监听的 bearer 鉴权 API-only 进程提供会话、模型、工作区和知识数据。工作台浏览器标签使用 WebKit 完整呈现外部 HTTP(S) 网页及其样式与 JavaScript。网页没有访问 Ark 凭据、工具或本地文件的桥接能力，应用主界面保持原生。

- 唯一面向用户的产物、应用名、菜单与窗口名为 `Ark.app` / `Ark`。
- 原生客户端每次启动生成一个令牌，以 bearer 凭据访问 loopback API；后台不提供浏览器界面。
- 进程使用产品数据目录，默认权限模式为只读，并禁用遥测。
- 本机构建使用 ad-hoc 签名；自包含构建为内嵌 Node 单独应用 V8 JIT entitlements，并在签名后执行真实 Node smoke。

聊天的处理详情展示已记录的调用配置与响应回执。请求型号与提供方报告型号分别显示；缺失或不支持的响应元数据保持未知。回执不能独立认证中转平台的底层型号，不暴露凭据，也不注入新的模型可见上下文。首响应计时对应首个流事件，不保证正文已经出现。吞吐率以提供方报告的输出 Token 数（可能包含思考）除以已完成模型流耗时之和，排除工具执行与重试等待。缺少计时依据时不显示吞吐率，而不借用其他调用的时间区间。

对话使用可移动的行渲染窗口，提供较早和较新内容的阅读入口。阅读旧消息不会推进实时事件游标。离开底部时会保留当前显示的有界实时文本帧，即使回复结束或取消也保持不变，直到用户明确返回最新；完整消息、复制操作及真实生命周期状态继续更新。从轨迹返回时保留该会话的行窗口与阅读位置。[对话发布决策](../../../.agents/notes/implemented/bug-fix/2026-09-08-native-startup-and-markdown-batching.zh.md)负责该显示策略。历史预览必须载入完整正文后，才提供整条消息操作。Markdown 表格各行共用按内容测量的列宽，长单元格换行；总宽度超过对话区域时保留原生横向滚动。

顶栏通过 Launch Services 在访达或终端中打开选定工作区，并提示目录不可用或启动失败。连接指示同时反映两条事件通道。手动重连会替换套接字循环，保留原有消息队列与消费者；只有后续基线能确认连接健康，关闭过程会阻止重连任务重新启动循环。

归档行通过原生上下文菜单和具名辅助功能操作提供恢复与永久删除，无需悬停。归档变更运行期间，两种操作均禁用；永久删除仍须单独确认。紧凑的悬停控件与日期保留各自现有显示状态；[归档操作决策](../../../.agents/notes/implemented/bug-fix/2026-10-20-native-archive-action-reachability.zh.md)记录辅助功能与布局的取舍。

模型设置以卡片集中呈现知识连接，模型选择对齐，独立向量服务按需展开，并提供明确的恢复与保存操作。展开后的向量字段保留可见标签，包括安全密钥输入框。保存连接不代表实际模型调用已经通过验证。

知识研究只允许一个活动操作。重复按回车或点击按钮不会再次提交；取消、切换项目和退出会使其结果失效，取消传输并等待所属任务结束。每次请求冻结 Host 公布的研究总预算，另加三十秒用于清理和传递，同时约束传输等待与绝对期限；普通 RPC 请求保留六十秒超时。研究预算缺失或无效时禁用提交，失败或超时的请求不会显示完成通知。

## 构建

```sh
zsh build-app.sh /path/to/output
```

在输出目录产出 `Ark.app`。图标源为 `Resources/AppIcon.png`，由用户提供的 Ark 素材派生的方形银色图标母版。构建统一为 1024 × 1024，并在临时目录生成 ICNS。应用内品牌使用 `ArkBrandView.swift` 中共用的原生矢量路径，深色模式呈现柔和银灰渐变，浅色模式呈现石墨灰渐变。路径可缩放为侧栏小图标，不带透明位图毛边。

构建细节、版本号与两种布局见[工程说明](../docs/engineering.md)。
