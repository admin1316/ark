## Rust candidate seam in the source snapshot

The working tree now exposes an optional, default-disabled Rust search candidate in `KnowledgeWikiService`. Shadow mode is observational: it sends a bounded immutable page/query DTO to an isolated child process, checks the input and result digests plus canonical BM25 equality, and keeps the TypeScript result. Candidate failures, cancellation, timeout, or divergence fall back to TypeScript. Enforce mode is deliberately rejected until Rust covers the complete hybrid BM25-plus-embedding contract. This seam is testable in a candidate profile, but the active Ark profile remains TypeScript-only and the acceptance audit remains `UNKNOWN` without production-boundary receipts.

The Rust kernel reuses one prepared BM25 index across a request's query batch. The maintained three-run benchmark uses 30 samples per run; TypeScript and Rust result digests match in every maintained replay, and the independent differential replay reports exact equality. On the file-backed one-query shape used by Ark `modelSearch`, fresh-child Rust IPC p50 is 16.953–17.466 ms, current TypeScript is 10.653–10.865 ms, and optimized TypeScript that rebuilds its index is 9.097–9.259 ms. Rust is therefore about 59–62% slower than current TypeScript and 86–90% slower than optimized TypeScript on this production-shaped path, so the decision remains `RETAIN_TS` and Rust enforcement stays disabled. A separate in-memory five-query batch measures Rust at 7.253–7.285 ms versus current TypeScript at 12.113–12.197 ms, but optimized TypeScript is 2.983–3.016 ms with a rebuilt index and 0.508–0.513 ms with a warm index; that batch does not match Ark's one-query call shape. These synthetic results do not establish production-corpus or long-run performance. Cross-platform runs, persistent-worker lifecycle, child CPU/RSS, cancellation, and crash recovery remain unmeasured. See the [repeatability receipt](../../scripts/rust-migration/knowledge-search-benchmark-repeatability-20261010.json), [differential replay receipt](../../scripts/rust-migration/knowledge-search-differential-replay-20261010.json), and [Rust candidate matrix](rust-candidate-matrix.md#current-benchmark-snapshot--2026-10-10).

The working tree also includes a launcher-owned external verifier adapter with signed child-process results and promotion seals. It runs through the managed `ctx.subprocess` owner, bounds output, and waits for the complete process tree to exit before returning. The profile exposes only the launcher-owned `knowledgeVerifierConfig` seam and the active value is empty; candidate verification therefore remains explicitly unavailable in the current product. Isolated fixtures verify configuration binding and process cleanup without claiming production acceptance.

### Utility outcome replay guard — 2026-10-10

`recordKnowledgeOutcome()` allows each non-neutral outcome only while the project's hash-chained journal contains an unconsumed retrieval for that page.
