# Rust candidate matrix

English | [中文](rust-candidate-matrix.zh.md)

This reference records the Rust migration decision from the checked-out source tree. It is evidence for planning and review; it does not enable a Rust provider or change an existing wire contract.

## Source evidence

The source-truth baseline at `b8adf5a7ec9c22c3f1c7958821af825bd7821d7a` and GitHub `origin/main` at `d382723905742f2b87401ad444d02756f5cb229b` had no `Cargo.toml` or Rust source files (`*.rs`) when inspected with `git ls-tree` on 2026-10-07. The current working tree now contains an isolated, non-production shadow crate at [`rust/knowledge-search-shadow`](../../rust/knowledge-search-shadow), added after that baseline. The native implementation that is present is a small C11 Landlock launcher in [`native/landlock-run/packages/entry/src/main.c`](../../native/landlock-run/packages/entry/src/main.c), exposed through the TypeScript entry module [`native/landlock-run/packages/entry/src/index.ts`](../../native/landlock-run/packages/entry/src/index.ts). Its contract is a process launcher and filesystem confinement probe, so it is outside the Rust kernel candidates below.

The knowledge kernels remain in-process TypeScript. BM25, tokenization, and cosine similarity are implemented in [`packages/host/knowledge-wiki/src/search.ts`](../../packages/host/knowledge-wiki/src/search.ts); graph traversal and Louvain community detection are implemented in [`packages/host/knowledge-wiki/src/graph.ts`](../../packages/host/knowledge-wiki/src/graph.ts). The current working tree has a deterministic optimized TypeScript comparison in [`scripts/rust-migration/benchmark-knowledge-search.ts`](../../scripts/rust-migration/benchmark-knowledge-search.ts), an isolated Rust shadow replay in [`scripts/rust-migration/differential-replay.ts`](../../scripts/rust-migration/differential-replay.ts), and a default-disabled production candidate seam in [`packages/host/knowledge-wiki/src/rust-search-candidate.ts`](../../packages/host/knowledge-wiki/src/rust-search-candidate.ts). It still has no production N-API provider or enforced Rust owner for these kernels.

Cancellation and child-process recovery remain owned by the existing TypeScript runtime. [`packages/subprocess/subprocess-local`](../../packages/subprocess/subprocess-local) terminates managed process groups through `AbortSignal`, and [`packages/jobs/jobs-local`](../../packages/jobs/jobs-local) owns task cancellation and teardown. The migration boundary must preserve those owners.

## Candidate decisions

| Candidate | Current owner | Rust boundary | Evidence status | Decision |
| --- | --- | --- | --- | --- |
| Tokenization and BM25 scoring | `knowledge-wiki/search.ts` | Immutable UTF-8 request bytes and page records; deterministic result bytes | Optimized TypeScript and isolated Rust shadow match the deterministic corpus; no real boundary or end-to-end replay | **RETAIN_TS** |
| Cosine similarity | `knowledge-wiki/search.ts` | Immutable numeric vectors; deterministic scores | No optimized TypeScript or Rust implementation; embedding calls dominate hybrid search when enabled | **RETAIN_TS** |
| Wiki graph derivation and Louvain | `knowledge-wiki/graph.ts` | Immutable page/edge records; deterministic graph result | No optimized TypeScript or Rust implementation; filesystem traversal and graph semantics need a replay corpus | **RETAIN_TS** |
| Incremental search or graph index | No separate index owner; search and graph rebuild from the Wiki tree | Versioned canonical index bytes with generation and checksum | No index format or rebuild/recovery contract exists | **DEFER** |
| JSONL or compressed-frame scanning | Session persistence and query packages | Read-only byte ranges with a bounded sequence range | Existing persistence and SQLite/zstd paths are mature; no Rust comparison | **RETAIN_TS** |
| Batch hashing or summaries | `packages/util/crypto` and knowledge ingestion | Canonical bytes and bounded batch size | No workload or end-to-end benchmark | **RETAIN_TS** |
| Long-running child process | Existing subprocess and jobs packages | Request ID, generation, deadline, budget, and cancellation token only | Process-group cancellation and teardown tests already exist; a Rust child would add a second supervisor | **RETAIN_TS** |

`RETAIN_TS` means that no Rust implementation may be selected for production. `DEFER` means that an index contract and replay corpus must exist before implementation work starts. The C11 Landlock launcher remains the existing native confinement provider; this matrix does not classify it as a Rust candidate.

## Required evidence before any candidate can move

Every candidate must be registered with a fixed input corpus and compare all three implementations:

1. Current TypeScript implementation.
2. An optimized TypeScript implementation with the same observable contract.
3. A Rust implementation invoked through the real N-API or IPC path that production would use.

The benchmark record must include the repository Git SHA, profile name, corpus hash, implementation versions, and toolchain versions. It must report cold and warm p50/p95/p99 latency, CPU time, Node plus native RSS, event-loop delay, serialization and copy cost, FFI or IPC cost, cancellation latency, crash-recovery result, build time, CI time, package size, and platform failure rate. An internal Rust microbenchmark is insufficient evidence.

The differential replay must compare canonical result bytes and error classes for the same request sequence. A mismatch, timeout, version mismatch, process crash, or cancellation failure keeps the candidate in shadow mode and records a TypeScript fallback result. Shadow mode must not emit duplicate production events or repeat an external side effect. Enforce mode is only allowed after replay and reliability thresholds pass; it fails closed on any subsequent mismatch.

Learning claims use the deterministic reducer in [`scripts/rust-migration/evaluate-learning.ts`](../../scripts/rust-migration/evaluate-learning.ts) and its documented input contract in [`scripts/rust-migration/README.md`](../../scripts/rust-migration/README.md). It requires independently verified baseline/candidate records with matching model, task, goal, and policy hashes; incomplete pairs produce `UNKNOWN` instead of a pass.

Rust inputs are limited to canonical bytes or immutable DTOs plus `requestId`, `sessionId`, `generation`, capability, deadline, budget, and cancellation token. Cordis contexts, agents, sessions, tool definitions, credentials, JavaScript callbacks, mutable JavaScript objects, and global services remain outside the boundary.

## Current conclusion

The synthetic file-backed knowledge-search fixture compares current TypeScript, rebuilt-index TypeScript, the production root-local cached TypeScript path, fresh-child Rust IPC, and a benchmark-only persistent Rust worker; the canonical result arrays match in the maintained runs. The warm cached TypeScript path is now owned by `WikiSnapshotStore`, with explicit write and watcher invalidation, but this source benchmark is not the complete production evidence set: real user Wiki behavior, candidate-profile execution, total child-resource accounting, production Rust worker ownership, cancellation, recovery, and cross-platform measurements remain open. No Rust migration is justified for production yet. Keep the existing TypeScript kernels and native C11 confinement provider, preserve TypeScript fallback, and retain the `RETAIN_TS` decision until the production evidence is complete.

## Current benchmark snapshot — 2026-10-10

Three fresh 30-sample runs of the maintained benchmark runner used the same 240-page synthetic Wiki corpus and produced identical TypeScript/Rust result digests. For the in-memory five-query batch, p50 ranged from 12.113–12.197 ms for current TypeScript, 2.983–3.016 ms for optimized TypeScript rebuilding its index per batch, 0.508–0.513 ms for the prebuilt warm-index scenario, and 7.253–7.285 ms for Rust IPC. For the file-backed one-query path, p50 ranged from 10.653–10.865 ms for current TypeScript, 9.097–9.259 ms for rebuilt-index TypeScript, and 16.953–17.466 ms for Rust IPC; fresh-child Rust IPC is 1.86–1.90× slower than rebuilt-index TypeScript. Ark's current `modelSearch` handles one query per call, so the batch result does not establish a production win. Keep production on TypeScript. The warm-index TypeScript result remains a benchmark-only cache scenario without a production owner or invalidation contract. The independent [differential replay receipt](../../scripts/rust-migration/historical-evidence-index.tsv) reports exact digest equality. The older aggregate's contradictory `allCanonicalResultsMatch: false` entries remain preserved and unresolved; see the [three-run maintained-runner receipt](../../scripts/rust-migration/historical-evidence-index.tsv). This synthetic benchmark still lacks production persistent-worker integration, child CPU/RSS, cross-platform, cancellation/recovery, production-corpus, and ACL/path-isolation evidence, so overall Rust acceptance remains UNKNOWN.

Each file-backed 30-sample fixture traversed the same temporary 240-page Wiki with embeddings disabled through current `hybridSearch`, rebuilt-index optimized TypeScript, and the candidate Rust IPC helper. Both isolated runs produced identical ranked-result arrays. The helper path performs a fresh traversal, computes the canonical TypeScript oracle, serializes the request, starts one Rust child, and checks the result; this invocation-local `enforce` comparison did not change the active profile, which remains disabled. The second run's measured latency was:

| File-backed route | p50 | p95 | p99 | Node-parent CPU / 30 samples |
| --- | ---: | ---: | ---: | ---: |
| Current TypeScript `hybridSearch` | 10.862 ms | 13.487 ms | 13.730 ms | 488,113 µs |
| Optimized TypeScript, index rebuilt per sample | 9.129 ms | 11.091 ms | 11.183 ms | 420,699 µs |
| Rust IPC candidate helper with TypeScript comparison | 17.319 ms | 18.572 ms | 18.592 ms | 625,204 µs |

Across the two file-backed runs, Rust p50 stayed 57–59% slower than current TypeScript and about 88–90% slower than rebuilt-index TypeScript. This supports retaining TypeScript for Ark's current one-query search path, not a production speedup claim. The Rust child CPU/RSS is excluded from the parent totals. Its first child took 415.544 ms in one run and 22.765 ms in the other; those first-call measurements follow TypeScript probes with uncontrolled process/filesystem cache state and remain a startup-risk observation, separate from the subsequent 30-sample distributions. The second run's 1 ms event-loop histogram measured mean excess of 9.890 ms for current TypeScript, 8.773 ms for rebuilt-index TypeScript, and 1.269 ms for the async Rust IPC wrapper (with 9.667 ms p95 excess for Rust). A warm TypeScript index remains a cache-only scenario. Real user Wiki data, ACL/path isolation, production-profile execution, child-resource accounting, a persistent production worker, cancellation, crash recovery, and cross-platform results remain unmeasured. Benchmark status stays `unknown`, and the production decision stays `RETAIN_TS`.

### Follow-up TypeScript scorer trial — 2026-10-10

A temporary `scorePages` refactor precomputed per-page term-frequency maps and title-token membership. Against the pre-trial current-TypeScript baseline in `rust-benchmark.json`, in-memory single-query p50 improved by 7.16–11.67%, but p99 regressed by 3.70–4.57%. ### Persistent Rust worker benchmark — 2026-10-11

Three fresh 30-sample runs used the same 240-page synthetic Wiki and checked every Rust response against the TypeScript oracle. The benchmark-only Rust JSONL worker received 33 requests in each process (one cold request, two warmups, and 30 timed requests); all three worker processes exited normally and all three differential replays matched. Across the three run-level distributions, median p50 was 14.800 ms for persistent Rust, 17.129 ms for fresh-child Rust IPC, 10.689 ms for current TypeScript, and 9.541 ms for optimized TypeScript rebuilding its index. Reusing the Rust worker reduced Rust p50 by 13.60% relative to starting a child for each query, but remained 38.46% slower than current TypeScript and 55.11% slower than rebuilt-index TypeScript. Its median p95/p99 were 15.638/15.940 ms, versus 12.968/12.972 ms for current TypeScript. The persistent worker is therefore not a speed win for the production-shaped one-query route; `RETAIN_TS` remains the decision.

The three clean exits and matching replays show repeatable completion for this bounded synthetic protocol test only. They do not measure Ark stability, production worker ownership, cancellation, crash recovery, long-running stress, child CPU/RSS, cross-platform behavior, real Wiki content, or ACL/path isolation. The JSONL mode is benchmark-only and disabled in all profiles. See the [aggregate receipt](../../scripts/rust-migration/knowledge-search-persistent-benchmark-20261011.json), its [three run receipts](../../scripts/rust-migration/knowledge-search-persistent-benchmark-20261011-run1.json), [run 2](../../scripts/rust-migration/knowledge-search-persistent-benchmark-20261011-run2.json), and [run 3](../../scripts/rust-migration/knowledge-search-persistent-benchmark-20261011-run3.json).

### Production cache and Rust on the one-query path — 2026-10-11

The reproducible [`--series` benchmark](../../scripts/rust-migration/knowledge-search-cache-vs-rust-reproduction-20261011.json) runs three independent 30-sample comparisons over a file-backed synthetic 240-page Wiki with one BM25 query per request. Exact results matched in all three runs and all three Rust workers exited cleanly. Median p50/p95/p99 were 10.109/11.072/11.577 ms for TypeScript rereading files and rebuilding the index, 2.172/3.024/4.048 ms for optimized TypeScript rebuilding from parsed pages, 0.095/0.127/0.195 ms for the production `WikiSnapshotStore.get` warm hit plus scoring, 6.631/6.881/7.032 ms for fresh-child Rust IPC, and 4.079/4.595/5.554 ms for the benchmark-only persistent Rust worker. Production index misses cost 11.126–12.902 ms. The warm-cache p50 is about 43× faster than persistent Rust; Rust only beats the file-reparse TypeScript path, not optimized TypeScript or the actual warm path, and it transmits page records for each query. This source-bound reproduction supersedes earlier one-off figures whose harness omitted the same cache-lookup boundary. With a 1 ms histogram resolution, event-loop-delay p95 for current TypeScript, rebuilt-index TypeScript, warm cache, fresh-child Rust, and persistent Rust was 12.403/2.517/1.020/6.885/1.596 ms; sample counts were uneven (29/29/3/29/93), so treat these values as diagnostic. Rust child CPU/RSS were excluded. The comparison also excludes provider/model latency, embeddings, verifier/ACL, stress, production cancellation and crash recovery, and real Wiki content. It does not establish Ark end-to-end speed or stability. Rust remains disabled and `RETAIN_TS` remains the production decision.
