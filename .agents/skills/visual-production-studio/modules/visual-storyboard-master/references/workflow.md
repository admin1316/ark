# 模块: workflow（visual-storyboard-master 子模块，按需加载）

## 工作流

### 1. 接收与规范输入

提取媒介、画幅、时长、帧率、视觉模式、剧本版本、角色资产、场景资产、道具、已有镜头表和交付格式。输入不完整但不影响安全与核心结构时直接采用合理默认值，并标为推定。

若输入是 Director Master 九列分镜，保留原镜号和镜头意图；若输入只有小说或剧本，先按戏剧节拍生成最小镜头清单，再进入画格设计。

### 2. 建立连续性圣经

建立不可随镜头漂移的锁定项：

- 角色：身份 ID、年龄、脸型、发型、体型、服装层级、鞋、伤损、随身物。
- 场景：平面关系、入口出口、地标、尺度、主光源、时间天气。
- 道具：归属、所在手、朝向、开合或破损状态。
- 画面：画幅、安全区、色彩模式、线稿或块面标准。

角色或场景有本地参考图时，生成前先查看参考图；每次只向生成工具提供该镜头必需的参考，避免无关资产污染。

### 3. 建立空间与轴线

每场先画或文字化一张最小平面图，确定人物站位、入口、视线轴、动作轴、摄影机可用侧、地平线、主要消失点和运动路径。没有空间定义，不得批量生成画格。

### 4. 设计关键画面

先确定戏核，再选择能够承载它的关键姿势与构图。每个画格只承担一个主要叙事目的。按需读取：

用户要求细致表情、哭戏或表演递进时，必须先完整读取 [真人微表情与连续表演合同](../../_shared/micro-expression-performance-contract.md)。先把每个人物镜头的表演拆成进入状态、刺激、微反应、压制、决定、防线破口和余波，再选真正需要画出的关键阶段；不得只画高潮表情，也不得把完整情绪过程压进一张画格。每个画格记录 `performance_state_id` 以及上一/下一状态；全景画重心和空间，近景画面部，背影画耳颈肩手。

- 课程能力地图：[course-capability-map.md](course-capability-map.md)
- 完整制作流程：[workflow.md](workflow.md)
- 输出字段和命名：[output-contract.md](output-contract.md)
- 连续性与视觉质检：[visual-qc.md](visual-qc.md)

### 5. 生成独立画格

- 一个镜头一次生成，不要求模型在一张图里同时画多格。
- 提示词只描述当前可见瞬间，并同时带入必要的身份、空间和状态锁。
- 画格内部不生成镜号、对白、箭头或复杂文字；这些由分镜板排版层添加。
- 动作镜头根据需要生成开始姿势、接触姿势、结果姿势；不能用一张模糊姿势代替完整动作逻辑。
- 表情变化镜头使用同一镜号的 `-A/-B/-C` 子画格；眼线、眨眼、泪膜、泪痕、鼻红、嘴唇和呼吸状态必须沿时间单向连续。
- 失败时只重做失败镜头，不重生成整个场次。

使用当前会话真实可用的图像工具。若没有图像生成能力，交付逐镜提示词、状态清单和分镜清单，不得宣称已生成画格。

### 6. 组装与校验

把镜头信息保存为 `storyboard.json`，运行：

```bash
node scripts/validate_storyboard.mjs storyboard.json
node scripts/render_storyboard.mjs storyboard.json storyboard.html
```

验证失败必须修正后再交付。HTML 分镜板支持浏览器查看和打印为 PDF。

## 生成决策

每个镜头按以下顺序确定，不留 `或`、斜杠选项和未决参数：

叙事目的 → 观众信息位置 → 关键姿势 → 角色与场景关系 → 画幅与画格能量 → 景别 → 机位高度与轴线侧 → 焦段 → 地平线与消失点 → 前中后景 → 明暗结构 → 运动箭头说明 → 连续性状态。

## 不可违反的规则

- 先建立空间，再画覆盖镜头；先调度人物，再决定摄影机。
- 画格服务故事，不用华丽细节掩盖动作、关系或信息不清。
- 感知先于反应，准备先于动作，接触先于结果。
- 表情先有触发再变化；单张静帧只冻结一个表演阶段，不写连续发生的多级崩溃。
- 不无意越轴；需要越轴时必须设计中性镜头、移动过轴或明确的新轴建立镜头。
- 近大远小、接地点、地平线、消失点和角色尺度必须自洽。
- 同场角色不得换脸、换衣、换手持物或无原因改变伤损。
- 不把 AI 生成文字当作可靠标注；编号和对白在排版层完成。
- 不复制、嵌入或公开分发课程原图和大段原文。课程只作为用户私有素材中的方法来源，技能保存抽象规则与来源说明。
