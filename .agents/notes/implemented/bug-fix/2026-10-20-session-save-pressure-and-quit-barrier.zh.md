# Agent Note: 保存压力与显式退出确认

Status: implemented

[English](2026-10-20-session-save-pressure-and-quit-barrier.md) | 中文

## 问题

有界批处理限制的是主动调度等待，不是慢写或失败写入之后保留的总量。若活动批次在收到确认前就移出待处理数组，简单的队列计数也会漏掉其字节。原生退出期限不能证明保存完成，活动 Session 列表也不包含退休失败的已移除所有者。即便没有新入队事件，种子初始化仍可能未确认。若退出代次无法独立校验，已取消的退出请求在新请求之后迟到时，仍可能重新关闭准入。

## 决策

持久化所有者对未确认的初始化后缀、活动批次及待处理事件准确计数一次。失败写入保留其顺序及原子边界。初始化保留原操作供显式重试，包括零事件的失败；准确生命周期只有在成功退休并收到确认后才释放。`flushAll()` 排空保留的活动与已退休所有者、初始化以及按 id 串行操作链，直到完全停稳。活动 Session 注册表不是保存所有权清单。

后端的 `writePressure` 配置在高水位暂停生产者，在低水位恢复。默认单 Session 为 4/2 MiB，协调器聚合为 32/16 MiB，生产者等待为 30 秒。计数代表等待确认的序列化事件字节，不是总堆占用，也不是通用内存上限。检查点在模型请求、顶层工具分派与步骤推进前等待；流式过程在 chunk 交给消费方后检查容量。失败、取消或到期结束生产 Agent 的等待，同时保留其 inbox 及独立拥有的写入器。

存储包装器在检查点后委托工具执行。既有 ToolExecutor 拥有工具正文进入前的最终取消检查，包括后续分派包装器引入的取消。

存储不可用或退出准备活动时，Host 拒绝新的消息/命令准入与 Agent 发布。已有匹配回执仍可确认，无需另一轮调用。退出尝试关闭准入、取消全部已注册 Agent，等待其空闲边界与已进入的命令操作，然后等待持久化屏障。只有完成这一序列才授权 `safeToQuit`；单凭空计数不成立。

Host 提供非负的 `quitEpoch`。prepare 与 cancel 携带已观察代次及不透明尝试身份。取消推进代次并重新开放准入；旧代次请求只观察当前状态，未来代次会被拒绝。相同当前准备请求加入原所属尝试，显式重试可重启失败尝试。原生监控拒绝新动作之前捕获的旧观察，仅接受属于自身身份及代次的就绪结果。界面拆卸前还必须保存原生草稿。二十秒后，原生提示提供等待/重试、取消退出或显式强制退出；时间经过本身绝不杀死未确认写入器。既有有界进程停止在验证保存后或用户明确选择强退后运行。尚未就绪且未接收原生输入的启动阶段仍使用所属后端清理。

Host 结算与原生 HTTP 响应是两个独立确认。验证 Host 保存后，或已观察到后端退出时，原生拆卸会取消剩余响应观察，并在等待 composer 调用方之前等待真实传输结算。原日志保持未确认；取消不能虚构命令回执。普通调用方取消仍不停止命令所有者。开始不可逆原生拆卸时，会重新设置二十秒提示，持续提供等待及显式强退，直到完成；取消退出被禁用，因为已停止的模型不能原地恢复。

最终本机草稿屏障先冻结编辑和动作，覆盖键盘、AppKit 桥接及修改所有者，再结算 composer 工作并保存最新 composer 与 Workbench 缓冲，包含等待 Host 期间产生的编辑。最终 composer 写入失败时，每份草稿保留一份失败快照供重试，更新的快照取代旧快照。失败会保留挂载的冻结界面，提供重试及显式强退，不会依据较早的草稿确认关闭。

冷启动附件恢复失败也属于该屏障。显式最终重试等待既有恢复所有者，仅在验证恢复的完整内容后清除失败状态。冻结草稿及附件日志必须与恢复的待提交记录相同；后续编辑或新增附件会保留可见失败，不会被覆盖或作为删减内容保存。恢复保留结果未确认的提交身份及发送参数，不提交工作。取消或关闭会抑制迟到安装，恢复成功后仍须完成最终持久保存。

附件恢复操作依据未解决的恢复状态显示，不依赖共享的 composer 临时消息。历史加载或编辑可以清除该消息，composer 仍根据既有失败标记生成恢复提示。显式恢复尝试清除上一条临时消息，并报告自身失败；仅经验证的恢复可以清除失败标记。显式重试与最终保存会比较当前草稿、附件日志及恢复快照。正文或附件变化不自动合并；用户需要检查不一致，或明确移除未恢复引用。原待提交记录与结果未确认提交的内容和身份保持不变。

提交的终态确认同时拥有原迁移草稿。目标会话身份等于捕获的创建身份时，即使重启后从目标会话发起重试，成功或已确认的命令错误也会确认匹配的首页回执。来源确认在单次 actor 操作内比较完整捕获文档与附件，匹配后才写入既有空 pending 记录。共享草稿提交与附件丢弃所有者清除匹配的偏好、附件缓存和日志指针，防止导航再次保存已退休输入。后来的正文、版本或附件即使沿用同一提交身份也保持完整；unknown 与 running 结果保留两份回执。成功与确认错误路径共享这一来源确认。

生命周期释放在 Host 就绪后仍保留持久 inbox。工厂共同拥有方与 continuation 排空把 `keepInbox` 传递给每个子级与 handle，并在等待完全停稳前标记释放，防止维护阶段唤醒保留的工作。显式 handle 与选定子级释放仍默认丢弃输入。终态观察器读取已停稳的 inbox 投影；保留工作属于已停止，不能报告完成。

取消会清除被取消活动已经登记的唤醒请求，即使其 inbox 被保留。之后显式发送的唤醒输入可以登记新的请求；仅取消退出不会重启已暂停的工作。

## 考虑过的替代方案

**丢弃流式 chunk，或在批次开始时清空计数。** 这会改变会话证据或隐瞒未完成写入。以确认计数及生产者压力保留完整日志。

**生产者或传输超时就取消磁盘写入。** 调用方无法知道追加是否已提交。取消观察保留单一写入器，允许稍后确认，避免引入竞争重试。

**只刷新已注册的活动 Session。** 注册表移除后，退休及初始化失败仍有所有者。这会丢失重试路径，也可能错误授权退出；持久化所有者已持有完整清单。

**只记住最近取消的尝试 ID。** 跨两次取消迟到的请求会重新获得准入。单调代次无需不断增长的取消集合，就能拒绝任意旧请求。

**把原生期限视为保存成功。** 期限只计量经过的时间。保留界面及显式强退选项，让用户控制未确认数据。

**只在开始退出时刷新本机草稿。** 等待 Host 时仍可能继续编辑。最终快照前的冻结让最后版本拥有独立保存屏障。

## 验证

合成的真实 Loader/JSONL 运行使退休与种子初始化失败，观察准备失败，恢复存储，再确认同一尝试到达 ready 且保留事件为零。已注册 Agent 路径以脚本化外部输出、无 API Key 的方式覆盖流式压力、停滞写入取消与退出准备。原生契约拒绝畸形计数、虚假就绪、旧代次及取消后迟到的 ready 观察，也检查重试所有权与监控关闭。原生交互与安装包验收仍独立于编译及契约覆盖。

真实 `URLSession` 通过合成 `URLProtocol` 在命令身份进入本地日志后挂起其响应，同时 Host 存储回复到达 ready。拆卸必须触发传输取消、完成关闭，并保留同一日志身份，不发送另一条命令请求。源码契约确保拆卸提示仍保持计时，并要求在等待 composer 调用方前完成响应观察的结算。

原生草稿契约在等待 Host 时编辑，随后冻结所有者并挂起最终 flusher。真实临时文件系统障碍使 composer 与 Workbench 保存失败；恢复目录并重试后，必须能恢复最后冻结的正文。冻结期间拒绝迟到编辑、还原及保存动作。实际挂载的禁用 SwiftUI 桥接呈现只读 AppKit 编辑器，并拒绝 Return 和 marked-text 提交。

冷启动附件契约在真实 AppModel 与存储之间移走并恢复合成文档目录。最终重试恢复相同图片、文档引用及冻结提交参数，不调用 RPC；缺失或损坏的日志及更新草稿保持未确认。挂起的存储操作覆盖迟到恢复前的取消和关闭，并在观察取消后通过显式重试恢复。没有当前待提交草稿或附件偏好记录时，冷启动恢复也会呈现结果未确认的提交，包括最终重试前已修复的附件读取失败。存储缺失时，空读取结果不能确认该失败已恢复，会话切换后的普通恢复也保持这一限制。

真实 AppModel 契约在两种语言下组合存储缺失、成功读取历史及正文编辑，要求临时消息清除后仍有展示提示，并通过显式重试恢复完全相同的引用，不遗留已经解决的失败消息。后续修改正文或粘贴图片后重试会保留新输入及可操作的失败状态，不改变原待提交、结果未确认提交及附件字节，关闭时也保持这一限制。

冷启动 AppModel 契约在没有内存迁移表的情况下准备匹配的首页与目标回执。命令成功、已确认的命令错误及普通消息成功会退休原首页身份，unknown、running 及投递拒绝则保留该身份。真实导航返回首页、离开及最终保存不能复活已退休内容。每条终态路径都保留独立的后来首页输入，以及沿用同一身份的正文或图片变化。Actor 契约验证同身份的版本、正文、图片及文档变化保留完全相同的文件字节，仅完整内容匹配时写入空记录。

真实 Loader 测试携带已接受的子级与孙级输入到达 Host 就绪，停止整个 Loader，再由新的持久化拥有方读回两个原始身份。限定后代关闭也保留这两条输入；显式 handle 与选定子级释放则丢弃它们。准备失败保持空闲，直到显式继续后才各执行一次身份。维护阶段的关闭不能发起另一模型请求。

Host 退出准备取消带有既有唤醒输入的维护活动。释放维护后，必须在没有模型调用的情况下到达安全就绪，并仍持久保留原输入。取消退出后输入继续暂停；显式后续消息才按 FIFO 各执行一次保留与新输入身份。现有从中止到空闲窗口的后续消息测试继续验证新的唤醒行为。

## 后果

存储故障停止新生产，已有写入仍可恢复。真正停滞的写入器可能让保存无限等待，直到用户取消或明确强退；强退可能丢失未确认记录。这不保证外部工具副作用恰好执行一次，也不限制整个进程的内存。[语义检查点决策](2026-07-21-semantic-session-checkpoints.zh.md)保留分派与恢复的理由，[单控制器决策](../simplification/2026-07-23-collapse-persistence-flush-state.zh.md)保留串行化及接管的理由。[批处理决策](../architecture/2026-08-08-bounded-session-persistence-write-batching.zh.md)继续拥有调度节奏，与压力及退出授权各自独立。
