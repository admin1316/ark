# Agent Note: 原生归档操作不依赖指针悬停

Status: implemented

[English](2026-10-20-native-archive-action-reachability.md) | 中文

## 问题

已归档对话的恢复和永久删除按钮只在原生侧栏行被悬停时存在。辅助客户端无法调用辅助功能树中不存在的控件；没有持久操作入口的行也无法通过键盘或辅助功能导航恢复对话。归档 RPC 成功不能证明这些原生控件可达。

## 决策

每个[原生归档行](../../../../integrations/jiuzhang/native/Sources/JiuzhangShellUI/NativeArchiveSidebarView.swift)都提供整行原生上下文菜单，以及具名、本地化的辅助功能操作，不依赖指针悬停。行保留稳定的会话专属辅助功能标识，并以对话标题作为标签。现有悬停按钮保留紧凑位置并增加明确的本地化标签；日期、行高、已认可的 Ark 品牌及周围布局保持不变。

两种入口复用现有模型变更。恢复调用 `restoreArchivedSession`；永久删除只设置 `pendingDelete`，打开现有明确点名对象的破坏性确认框。取消只清除待确认意图，不执行删除。会话的归档变更运行期间，菜单项禁用，辅助功能操作拒绝调用。这些控件不绕过[注册表拥有的归档与删除生命周期](../feature/2026-07-31-session-archive-global-set.zh.md)。

## 已考虑的替代方案

**只保留悬停入口。** 指针事件改变行的本地状态之前，按钮始终不存在，使辅助导航依赖不由它拥有的鼠标交互。

**始终显示图标按钮。** 这能让控件容易发现，却会挤占日期并改变已认可的紧凑行布局。原生上下文菜单和具名辅助功能操作在保留该呈现方式的同时提供另一条调用路径。

## 验证

构建或现有原生契约套件不能证明菜单或辅助功能调用成功。恢复、取消、合成对话的确认删除、持久化，以及与已认可基线的视觉一致，都需要独立的候选交互证据。该证据记录真实原生操作与结果状态，不使用测试专用变更 API；本文不将 GUI 验收记为通过。

## 后果

归档操作保留唯一模型所有者和唯一删除确认，同时无需改变悬停状态即可调用。指针用户保留现有紧凑按钮，辅助客户端获得明确的具名操作。构建和源码检查仍不足以完成原生交互验收，测试专用变更路径也不能替代产品控件。
