# Agent Note: Native chat following keeps one interruptible animation

Status: implemented

[English](2026-09-27-native-chat-scroll-follow-single-flight.md) | 中文

## Problem

每次已接受的对话高度变化都会让正在跟随的 AppKit 聊天界面同步跳到新末尾。如果改成每个流式更新都启动一次新动画，后续更新会反复重启动画，也可能让读者失去对视口的控制。

在大型对话中，从流式输出的 24 行窗口切到完成后的 96 行窗口，会在最终回答排版时把更早的行插到视口上方。一次真实候选的 2 万片段合成运行显示：完整回答出现前，有一帧短暂显示了较早的回合。

## Decision

`ArkChatScrollCoordinator` 通过 AppKit 将底部跟随变化动画化，时长为 160 毫秒。`ArkChatScrollFollowMotion` 只保持一段动画；结束时读取当前测量到的末尾位置，不另存待处理目标。如果动画没有取得有效进展，就即时校正一次，避免原地循环。内容缩短或视口超出范围时也即时校正。滚动输入会先冻结当前呈现位置，并使旧动画完成回调失效，再由 AppKit 处理手势。减少动态效果设置、阅读锚点、会话切换和显式历史定位仍即时完成。

`ArkChatRenderWindow` 让大型对话的跟随窗口在流式输出和完成后都保持 24 个已装载行。用户滚到当前已装载页顶部时，会自动打开有界阅读窗口：首次扩展包含当前末尾，大型对话装载 96 或 160 行；此后每页与上一范围最多重叠 32 行。AppKit 协调器只会为用户主动滚到顶部发出一次带锁存的回调；离开顶部后重新允许触发，会话切换时清除锁存。每次前插前，视图都会捕获当前可见行，并在布局完成后恢复该锚点。当前已装载行全部展开后，同一手势会请求一页更早的数据库历史，并把原先的首行固定在顶部。原有按钮仍供鼠标用户使用。跟随窗口仍为 24 行，也没有新增第二个投影所有者或轮询循环。

## Alternatives considered

**保留同步跳到末尾。** 否决，因为每次对话投影完成都可能让视口离散跳动。

**每次内容变化都重启平滑动画。** 否决，因为流式更新可能在动画结束前再次改变目标，反复重启会与读者的视口位置争夺控制权。

**增加独立的 SwiftUI 滚动控制器。** 否决，因为现有 AppKit 协调器已经负责每个会话的阅读位置、用户意图和历史锚点；增加第二个控制器可能发出相互冲突的滚动操作。

**流式结束时扩大所有大型对话窗口。** 否决，因为额外行会在最终 Markdown 更新时改变测量高度，让跟随中的视口短暂移到较早回合。阅读者仍可明确操作翻页。

**只用“载入更早内容”按钮越过渲染窗口边界。** 否决，因为普通滚轮或触控板手势会停在偏移量零处，还要再点一次，长对话看起来就像滚动卡住。用户滚到顶部时自动翻页仍保持有界渲染，并在每次前插后恢复当前可见行。

## Testing

定向原生 `chat-scroll` 契约组通过，覆盖单段活动动画、当前几何位置交接、无进展时结束、内容缩短时校正、用户中断、减少动态效果时的同步定位及 AppKit 接线。旧目标、无进展及内容缩短回归先在旧代码上失败，修正后通过。撤掉临时定向测试入口后，完整 Jiuzhang 原生契约再次通过全部 53 组。一份仅含滚动改动的自包含运行时包与其源码校验一致，包含 164 个工作区包和 315 个物理包身份；更早的包因计划漂移被正式拒绝。仅含滚动改动的候选 3.1.1（`2026092703`）通过回执、依赖闭包、构建及严格签名检查。Launch Services 报告实际运行路径为 `~/ark-test/candidate/Ark.app`，标识和构建号符合隔离候选预期；正式版仍为 3.1.0（`2026092701`）。后续 Alpha2 审查又加入后台唤醒和排队消息修复，因此该候选不代表最终组合源码。

装载范围回归检查验证：601 和 4,444 个条目时，跟随窗口在回合完成前后都保持 24 行；4,444 个条目的阅读窗口在回合完成前后都保持 96 行。推动这一修正的视觉证据来自隔离的合成候选，不能算作修正后的视觉通过；正式晋升前仍需重建候选复测。

2026-09-28，修正前的隔离候选 `2026092811` 完成了 30 分钟合成运行，包含 20,000 个流式片段、一次工具调用和工具调用后的最终标记。候选 UI 无障碍树中能看到最终回答及工具结果；截图显示阅读者仍停在 A/1427–1428 回合。滚到已装载窗口顶部后，滚动偏移量到达零，界面显示“载入更早内容 (4,373)”；不点击该按钮就无法继续用滚轮访问更早行。这将滚动故障与消息送达区分开：最终流已经到达，但有界阅读页边界打断了连续滚动。候选进程监测共 1,831 个样本并通过，平均聚合 CPU 为 19.375%，聚合 RSS 峰值为 337,200 KiB，进程未退出。修复版候选的滚动复测仍待完成。

仅监听本机回环地址的模拟服务每次返回 180 行编号合成文本。四次 OpenAI 兼容请求全部完成，每次发送 469 个流式片段；没有使用真实模型凭据或外部提供方。候选窗口的流动中截图显示内容持续进入并跟随底部，完成后显示第 180 行。原生滚轮使读者在另一条仍在运行的流中停留于第 96–112 行；完成后仍可见同一范围，点击“回到最新”后第 180 行出现。轨迹页显示三轮合成事件，返回对话后完成的内容仍在。五张候选窗口截图及其摘要保存在 `~/ark-test/evidence/alpha2-scroll-20260927/`。测试占位令牌已从候选专用 Keychain service 删除，候选退出后其专用数据目录已清空。

通过设置保存手工声明的自定义提供方时报错 `provider does not own the requested settings namespace`；验收改用指向本机模拟服务的已有 DeepSeek 路由。这个独立的设置缺陷未纳入滚动补丁。与旧源码同状态的正式视觉对照、长时间重复压力运行和正式版晋升仍未验证。

## Consequences

实时跟随会平滑移向新内容，而用户手势和历史阅读仍按现有逻辑控制位置。一次末尾更新最多需要 160 毫秒完成；如果这段时间里内容继续增长，协调器会等当前动画结束后再跟随测量到的新位置。内容缩短和动画停滞时即时结束。

大型对话默认只装载最新的 24 行，直到阅读者明确向前翻页；这避免完成时自动扩大范围，同时保留通过现有翻页控件访问旧回合的能力。

大型对话中的读者滚到窗口顶部后会继续逐页访问旧内容，不必为了每页停下来点击；每次扩展仍有行数上限，并会保持用户当前可见的消息位置。
