# Agent Note: 可选删除缺失处理前确认目录祖先

Status: implemented

[English](2026-10-12-wiki-unlink-absence-ancestors.md) | 中文

## 问题

Windows 可能对普通文件之下的子路径返回 `ENOENT`。只凭该错误码认定可选文件缺失，会让 Wiki 清理掩盖无效路径，包括在打开目标前被替换的父路径。

## 决策

[文件系统 owner](../../../../packages/host/knowledge-wiki/src/filesystem.ts)在删除的两个缺失处理边界检查祖先。现有祖先遍历使用 `lstat`，传播检查失败，并在文件系统根处终止。只有最近的已存在父路径解析为目录，缺失才成为无操作处理。

对父路径的 `stat` 保留现有中间目录别名解析。最终目标的 `lstat`、`O_NOFOLLOW`、唯一链接检查、inode 比较、墓碑恢复及目录 fsync 仍由现有 owner 执行。没有新增平台专属删除实现或公开操作。

## 考虑过的替代方案

**保留只检查错误码的缺失判定。** 它会把 Windows 的无效祖先当作缺失接受。

**拒绝所有缺失路径错误。** 这会破坏真正缺失叶文件和父目录的幂等清理。

**要求直接父目录存在。** 缺失的嵌套层级仍可能有有效的已存在目录祖先，且不需要删除。

**逐个修补清理调用方或特判 Windows。** 共享删除操作可以统一执行该区分，无需复制策略或假设哪些平台复用某个错误码。

## 影响

缺失目标的清理增加祖先检查；已有目标的删除保持原有身份与持久化次序。[真实文件系统交错测试](../../../../packages/host/knowledge-wiki/tests/filesystem-races.spec.ts)固定了首次 stat 与打开前的拒绝、嵌套缺失、查找拒绝、根不可用、目录检查失败和中间别名行为。在 macOS 上映射错误不等于实际 Windows 执行或已安装候选验收。
