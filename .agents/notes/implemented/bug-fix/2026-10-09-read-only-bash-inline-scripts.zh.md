# Agent Note: 只读 bash 任务使用内联脚本

Status: implemented

[English](2026-10-09-read-only-bash-inline-scripts.md) | 中文

## 问题

只读计算可能在解释器启动之前就失败，因为 shell 使用临时文件传递 here-document。即使前一个任务给出了准确的最终答案，该失败仍会在新对话中重犯。要求对每次沙箱拒绝都升权的建议，没有区分这次附带写入与任务实际需要的访问。

## 决策

[字面量 stdin 决策](2026-10-09-bash-literal-stdin.zh.md) 取代了不向模型暴露 stdin 以及仅依赖内联脚本提示的选择，并保留本文的 shell 执行和环境变量归属。

[bash 工具](../../../../packages/shell/tool-bash/README.zh.md#model-experience)在其系统提示词区段中提供固定的跨调用指引：here-document、here-string 和临时脚本文件可能需要写入；正确引用的 `python3 -c` 或 `node -e` 参数可以在不进行这次临时文件写入的情况下完成允许的读取与计算。模型保持同一个沙箱，并检查报告的退出状态。这是有条件的建议，并不声称每种 shell 总会使用临时文件，或每个内联脚本都是只读的。

工具描述仅在任务确实需要被拒绝的访问、且更宽的模式可以允许该访问时允许升权。被拒绝的读取或写入，仍不能通过任何替代路径获取。现有审批顺序、执行器、命令 argv、受管环境、结果标记与协议格式保持各自的约定。共享升权提示报告可用的审批路径，并不判断任务是否需要该访问。

## 考虑过的替代方案

**为附带的临时文件写入升权。** 任务可以留在现有授权范围内时，这种做法仅为 shell 输入传递寻求更宽的权限。按现有审批策略，升权仍适用于实际需要的访问。

**自动改写 shell 命令。** 替换 shell 语法需要为任意命令保留引用、展开、解释器输入与取消语义。工具让模型控制命令，并通过现有归属方约束执行。

## 后果

指引适用于所有 bash 调用方，不改变执行器，也不授予文件系统访问权限。插件注册期间，固定文本增加输入 token，同时保留提示词区段现有的 scope 与缓存行为。结果仍可能携带原样的通用升权提示，因此其解读取决于常驻指引和任务实际需要的访问。

文本与无密钥回放检查不能证明真实模型会避开该失败。隔离的 Native 3.1.8 任务仍待验证。这次改动不提供经过验证的学习或跨对话修复复用证据、知识准入权威、Rust 迁移或实测速度提升。
