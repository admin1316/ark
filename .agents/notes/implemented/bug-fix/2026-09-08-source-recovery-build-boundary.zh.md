# Agent Note: 分离恢复源码与保留产物

Status: implemented

[English](2026-09-08-source-recovery-build-boundary.md) | 中文

## 问题

保留的运行时仍然可用，并不意味着恢复的源码没有缺失导出或不兼容声明。因为组合包已存在就跳过编译，或把已安装的组合包复制为构建输出，会掩盖这些缺口，无法证明可复现构建。

## 决策

Host 构建先编译源码项目图，再生成组合包，并传播第一个失败阶段。TypeScript 的 `noEmitOnError` 是编译器配置项；构建模式使用 `--stopBuildOnErrors` 阻止下游项目继续。已有产物是恢复输入，不是构建成功的证据。源码测试别名将 Remote 查找和事件模块解析到源码，而非保留的 JavaScript。

Host 聚合明确包含从 Ark 原生启动器与配置 profile 组合包可达的全部 workspace。清单图测试检查这些入口，防止遗漏的原生包逃过编译。原生消费方引用拆分 Remote 包的 Host 编译面，而非混合 Host/Client 源码的程序。

原生构建从同一运行时依赖所有者派生编译聚合。纯源码编译规划不能证明打包文件清单或已编译包有效；包规划仍要求并计算可执行产物的哈希。原生构建要求源码到输出映射，生成反射，并检查原生端点、严格结果、服务所有者和生成代码的运行依赖。即使编译成功，缺少端点仍使构建失败。旧 Web 检查保留自身结果。

恢复的调用关联引用使用现有 `CallId` 导出，不改变 wire 字段名或标识符值。Agent Context 适配器实现源码注册表要求的双向映射。身份识别检查权威存活 Agent 条目，因此已退役或使用相同 ID 的过期对象不能取得替代实例的身份。

## 考虑过的替代方案

**使用已安装组合包作为构建兜底。** 这能保留可运行副本，但会隐藏源码缺口，并让发布依赖某一台机器。应单独保存该副本。

**仅通过 ID 识别 Agent Context。** 被保留的 Context 可能比其注册表条目存活更久。比较确切的当前 Agent，能使退役在两个映射方向上都生效。

## 后果

真实编译器包装测试覆盖有效源码、拒绝源码、阶段顺序及类型错误时保留已有输出。Agent 注册表测试覆盖存活身份识别、缺席归属、过期实例和退役。这些局部契约不证明恢复源码树已通过全仓库门禁、自包含发布或原生验收。
