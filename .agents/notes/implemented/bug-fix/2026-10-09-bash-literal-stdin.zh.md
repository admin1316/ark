# Agent Note: 沙箱 Bash 工具的字面量 stdin

Status: implemented

[English](2026-10-09-bash-literal-stdin.md) | 中文

## 问题

macOS Bash 3.2 会在启动解释器之前把 here-document 输入写入临时文件。因此，只需要读取现有 CSV 的只读有理数计算也会失败。内联脚本提示仍让模型处理嵌套 shell 引用，没有暴露现有的进程输入通道。

## 决策

[Bash 工具](../../../../packages/shell/tool-bash/README.zh.md) 暴露可选的字面量 `stdin`，并通过现有 shell 和子进程提供方传递。模型以 `command: "python3 -"` 配合放在 `stdin` 中的脚本发送多行代码。命令保持原样执行；输入按 UTF-8 写入，随后关闭。省略输入时保留只有命令的行为，空字符串仍然有效。

工具在本工具的沙箱升权审批、任务注册或执行之前，按正安全整数配置 `maxStdinBytes` 检查 UTF-8 字节数。默认上限为 1 MiB；超限输入整段拒绝，不截断，也不回退到临时文件。受信任的进程内调用方保留现有 shell 请求约定。

两个字段都保留在普通的工具调用参数日志中。带 stdin 的调用使用现有通用执行卡片，以 `{command, stdin}` 作为原始输入；前台结果保留终端结果视图及其退出状态，让非零退出仍呈现为失败。只有命令的呈现、事件封装、环境变量保护、沙箱配置、取消、输出上限和进程清理仍由各自现有所有者负责。

这取代了 [stdin/env 决策](../architecture/2026-06-30-bash-stdin-env-trusted-plugin-api.zh.md) 中不向模型暴露 stdin 的选择，以及对[内联脚本提示](2026-10-09-read-only-bash-inline-scripts.zh.md)的依赖。工具仍禁止通过其他路径获取被拒绝的读取或写入。

## 曾考虑的替代方案

**在只读模式下允许临时写入。** 这会削弱所有共享该许可命令的既定文件策略。

**改写 here-document 或更换 shell。** 自动转换必须保留任意引用、展开、重定向和 shell 行为。较新的 Bash 对足够大的 here-document 仍保留临时文件路径，因此选择它不能提供通用解决方案。

**只保留内联脚本提示。** 嵌套引用和参数长度限制依然存在，而子进程提供方已经接受字面量输入并管理其生命周期。

## 后果

这个新增工具字段为获准的多行任务提供不需要临时文件的输入路径。它并不让任意未经修改的 Bash 3.2 here-document 成功：对应的写入拒绝仍有明确回归测试。真实模型仍可能选择该语法；原生候选验收必须检查每次工具结果，不能从源码变更推断通过。

已注册的 `bash-stdin` headless 快照执行真实工具和命令，并在完整组装日志中保留字面量输入及其输出。针对性测试覆盖 UTF-8 大小边界、大输入、忽略输入、取消、请求传递、呈现、真实 Seatbelt 有理数计算，以及尝试写入后文件仍不存在。这些检查不能证明原生验收、跨会话学习或发布结果。
