# Agent Note: 原生 Settings 所有权与保守机密投影

Status: implemented

[English](2026-09-09-native-settings-ownership-and-redaction.md) | 中文

## 问题

重建的 Settings 源码缺少应用保留的原生 Remote 方法、精确修订的生效结果和 namespace 退出屏障。脱敏后的值也可能通过未遍历的 schema 分支或 schema 默认值泄露凭据。取消观察者订阅不会停止已经运行的回调。

## 决策

现有 Settings 提供方拥有原生读取、写入和本地文档交接。通用 Remote 写入不能修改领域事务所有者保留的 namespace。回复均为独立副本；写入拒绝保留修订冲突，但不暴露存储或校验诊断。原生命令只接收提供方未变化的绝对路径和调用方取消信号。

提供方在提交通知前绑定完成结果，区分持久化和所有者回调成功。namespace 释放期间保留所有权，直到已接收的写入和已启动的回调完成，包括已经取消订阅的回调。超时的所有者会保留名称直到工作停止；旧 scope 不能通过替换后的注册写入。这扩展了[写入路径所有者](../architecture/2026-07-30-settings-write-path-integrity.zh.md)，其队列和持久化决策继续有效。

机密投影移除任意 union 或 intersection 分支声明的全部位置，不选择或执行分支。tuple 保留索引；机密数组位置变为 null。序列化默认值按其自身 schema 脱敏，包括含嵌套机密的父级默认值。不支持的含机密转换和无法解析的引用会被拒绝。这部分替代了[配置加固记录](2026-08-15-config-backup-and-redaction.zh.md)中的脱敏备选方案；其备份和诊断决策仍然独立有效。

字典键 schema 与值一起参与活动节点发现，因此原生表单元数据能够识别其序列化引用。投影值或默认值之前会拒绝含机密的键：把这种键保留在路径或脱敏对象中，本身就会泄露秘密。公开字典键仍受支持，不削弱对未知引用的拒绝。

每个被投影的层都必须独立具备可证明的机密容器形状。合法的解析值不能授权透传错误形状的 base、用户层或 schema 默认值。object、dict、array 和 tuple 值若不是缺失值、形状错误且 schema 含机密，就以不回显值的固定诊断拒绝。公开容器保留透传行为；未标记的 tuple 尾部仍不被自动分类为机密。

## 考虑过的替代方案

**第二套 Settings 桥接。** 它会重复写队列、取消和提供方路径所有权。现有服务已经拥有这些操作。

**先解析一个 union 分支再脱敏。** 解析可能转换值，也可能让同一个值通过限制较少的分支。取所有已声明机密位置可以避免这种依赖，代价是保守地多隐藏部分字段。

**原样保留 schema 默认值。** 表单元数据同样是协议载荷，也可能包含与解析值相同的凭据。

**只信任生效值校验。** 用户层可以遮住无效的 base 或默认值，但描述符仍可能暴露该下层。因此脱敏会检查它返回的每一个层。

## 后果

行为测试覆盖受保护写入、冲突、取消、路径变化、生效拒绝、延迟释放、失效 scope、原型形状的 JSON 键和 schema 默认值机密。真实 Loader 与文件型提供方的快照覆盖原生编辑持久化、生效、陈旧编辑器拒绝和卸载。覆盖率仍是独立的失败门禁；这些测试不代表已安装应用或正式发布验收。不支持的机密 schema 会被拒绝，未标记字符串不会被自动分类为凭据。
