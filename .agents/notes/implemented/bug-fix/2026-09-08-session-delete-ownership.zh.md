# Agent Note: 串行化会话删除与关联数据清理

Status: implemented

[English](2026-09-08-session-delete-ownership.md) | 中文

## 问题

永久删除不能与存活 Session、已预约的恢复或已准入写入竞争。仅删除日志会留下附件；关联数据清理完成前就报告成功，可能遗留反馈记录，或让待执行工作重新创建它们。

## 决策

持久化协调器等待退役，拒绝存活或已预约的身份，并通过已有的按 ID 写入链串行执行物理删除。仅在物理移除成功后丢弃准备缓存和写入状态。`session-persistence/deleted` 通知在释放该链后执行，并等待完成。关联数据清理失败时以重试指引拒绝请求；删除已经缺席的身份仍会重试通知。

JSONL 修改复用 [atomic-write](../../../../packages/util/atomic-write/README.zh.md) 的跨进程锁。删除会将普通会话目录移动到项目内确定的 `~delete` 暂存目录，提交命名空间变更，再移除其所属内容。发现过程排除这些待删除目录；重复删除会完成遗留目录的清理。符号链接形式的删除根目录和会话目录会被拒绝。SQLite 在一个验证过 schema 的事务中删除会话行及级联事件，不迁移 schema。

## 考虑过的替代方案

**在移除字节前，或持有写入链时发送通知。** 提前通知可能为一次失败的删除清空关联数据。持有写入链进行清理，则可能与读取持久化状态的订阅者发生死锁。

**新增一套根据 PID 自动移除过期文件的锁。** 检查 PID 后再删除路径，不能证明对替代锁文件的所有权。共享锁遇到遗留锁时拒绝修改，而不猜测移除是否安全；恢复仍需明确的运维操作。

## 后果

共享后端测试覆盖存活与预约拒绝、缺席会话重试、等待清理及订阅者失败。JSONL 测试覆盖相邻会话保留、所属附件、隐藏目录重试和符号链接拒绝，并在适用时覆盖两种编码。这些检查不证明真实断电恢复或生产晋级。遗留写锁可能阻止后续修改，直至检查其所有权并恢复；系统绝不静默删除该锁。
