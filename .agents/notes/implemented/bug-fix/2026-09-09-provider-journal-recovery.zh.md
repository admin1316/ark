# Agent Note: 不猜测修订号的提供方日志恢复

Status: implemented

[English](2026-09-09-provider-journal-recovery.md) | 中文

## 问题

应用重启会保留提供方日志，却重置 Settings 的内存修订号。只匹配这个数字可能覆盖较新的持久配置。仅保留事务 id 的原生客户端无法安全重建原始编辑；传输失败也不能证明操作未提交。保留的版本 1 日志还缺少重建写入方所用的已完成回执历史。

## 决策

[提供方事务 owner](../../../../packages/llm/llm/src/provider-transaction.ts) 把完整且摘要校验通过的版本 1 计划，读取为与当前回执日志相同的内部表示。两者都保留版本 1 grant 封装；`receiptVersion: 1` 标识当前回执历史。查询不改写任何一种格式。显式修改或恢复会先认领精确的已存记录，再写入当前格式，保留可用的事务身份与终态回执，不猜测已经丢弃的历史。

新计划绑定原始用户分节的摘要。恢复只有在摘要仍匹配时，才能使用新的内存修订号。未提交编辑若缺少该证明，或原状态已改变，恢复会保留已存配置并记录已回滚结果。已经应用的编辑可以不重复执行而完成对账。未知格式、缺失计划、无效摘要与不受支持的操作字段会被拒绝，不清空数据。这些规则取代[端点代际记录](2026-09-06-provider-endpoint-generation-replay.zh.md)中仅凭修订号续跑和猜测请求绑定旧日志的做法；其中的代际与精确输入溯源规则仍然有用。

`llm/providerTransaction` 返回保留的阶段或终态结果，不返回计划内容或秘密值。`llm/resumeProvider` 接受提供方、事务 id 以及可选的只写缺失凭据，并在[既有共享服务租约](2026-09-06-provider-transaction-execution-ownership.zh.md)下执行已存计划。对象键序与刷新后的修订号不改变当前重试身份；数组顺序和业务值会改变。已完成回执保持不可变结果，包括已持久化但未激活的失败。

当提供的凭据引用已配置或已属于该配置时，轮换使用确定性的新引用，包括同端点轮换。因此设置写入失败不会改变旧的活动密钥。暂存引用若已经包含不同值，会被拒绝。移除凭据等待激活完成；通用 Settings Remote 保护则分别属于每个调用方 fiber。[文件提供方](../../../../packages/settings/settings-file/src/index.ts) 在写锁内比较目标命名空间后才替换，保留未观察到的同级编辑，并拒绝目标漂移。

新凭据计划持久保存不含秘密的原状态。[Credentials owner](../../../../packages/credentials/credentials-local/src/index.ts) 在既有队列和文档锁内，对普通写入执行条件暂存与条件删除检查，包括钥匙串模式。终态成功在同一独占区间内检查结果引用，直到日志提交。已经改变的凭据会被保留，并产生 `committed-not-live`，而非成功回执。设置失败时，只有计划证明此前不存在且摘要仍匹配，才补偿删除新暂存值；清理失败保留可重试日志。缺少该证明的旧计划不能授权删除已有值。每次持久认领内部都会检查取消，包括排队后对终态记录的规范化。

原生 Settings 把状态与恢复动作绑定到调用方保留的事务 id。读取不创建 id，恢复必须显式触发，迟到回复也不能清除较新的 id。失败调用只有在终态得到证明后才释放待处理身份。运行时 dispose（资源释放）停止准入并等待已接收工作结束；激活 owner 消失会产生明确的已持久化但未激活结果，而不是成功激活。

## 考虑过的替代方案

**把不可读日志当作空存储。** 这会破坏唯一可用的操作身份，并可能重复已经提交的工作。

**猜测重启修订号或从界面重建操作。** 两者都无法重建原状态或原始意图；刷新后的表单可能描述另一个操作。

**覆盖同一凭据引用后再补偿。** 补偿无法找回局部写入中已丢失的旧秘密，因此暂存不能修改活动引用。

**为恢复状态新建数据库。** 现有凭据记录已经拥有持久事务；另一个存储会增加第二个提交边界。

**只检查最终凭据值。** 无条件的延迟移除可能已经删掉并发替换值；检查不存在无法发现这项丢失。条件删除必须在引用 owner 内、实际移除之前执行。

## 后果

安全恢复包含明确拒绝：不承诺成功续跑缺少原状态证明的旧计划，或没有操作内容的记录。即使后续运行时能加载已存配置，终态失败也保持终态。日志已经丢弃的更早事务身份无法重建。遗留文件锁不会被猜测或自动移除。

值摘要条件保护使用同一凭据文档的参与写入方，不保护任意钥匙串写入方或变回相同值的 ABA 改动。保留的旧计划无法证明已有的未引用秘密是否由该事务暂存；恢复会保留它，而不猜测删除。这种拒绝不等于凭据完整回滚。

[冻结的 fixture（测试前置数据）](../../../../packages/llm/llm/tests/fixtures/legacy-v1-journals.json) 是保留实现使用合成凭据生成并按字节固定的输出，不是改写后的当前格式样本。[行为检查](../../../../packages/llm/llm/tests/provider-transaction.spec.ts)、[新进程检查](../../../../packages/llm/llm/tests/provider-process.spec.ts)与 [Loader 快照](../../../../snapshots/native-provider-recovery.snapshot.ts)覆盖只读状态、规范化、陈旧及重复恢复、秘密安全的失败和重启。强制退出发生在持久写入释放文件锁之后；这不代表能从任意断电或遗留锁恢复。原生编解码与生命周期约定仍和候选包 GUI、正式版验收分开。
