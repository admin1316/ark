# Agent Note: 提供方事务执行所有权

Status: implemented

[English](2026-09-06-provider-transaction-execution-ownership.md) | 中文

## 问题

原子日志检查不能保护后续异步凭据写入。旧执行者等待凭据读取时，重复执行者可能完成同一事务，较新事务也可能提交。旧写入发生后才发现日志改变，无法恢复较新的值。

## 决策

现有 [LLM 事务 owner](../../../../packages/llm/llm/src/remote.ts) 在整个操作期间保留执行所有权。获取顺序依次为提供方日志、设置命名空间、所有移除或采纳的凭据引用；最后一级的键一起预留。固定获取顺序与拒绝嵌套事务回调共同避免锁顺序反转。提供方调用按先入先出顺序执行，无关资源集合可独立运行。

租约绑定 Cordis 的原始服务身份，而不是调用方的可追踪代理。已结算的 Promise 尾链和回调执行作用域不保存配置、秘密、修订号或持久化结果。现有设置修订号与事务日志仍是真源。新 陈旧 请求在凭据暂存前失败。对已完成收据的精确回放不重复修改配置或凭据，并拒绝重新变为活动状态的日志；既有旧日志升级只改变元数据。

认领前取消不改变凭据或配置。开始持久化认领是取消边界：常规提交或失败／恢复结算期间始终保留租约，包括 owner 回调。这样取消就不会把未完成的副作用暴露给下一个执行者。不会为了提前释放租约而丢下尚未完成、不可取消的 I/O。

[端点代际决策](2026-09-06-provider-endpoint-generation-replay.zh.md) 仍负责引用分配、请求绑定和持久化回放。执行所有权补充这些检查，不替代其溯源或拒绝不确定状态的行为。

## 考虑过的替代方案

**只在认领时或写入后检查。** 快照可能在凭据读取期间变为 陈旧，后续日志拒绝发生在破坏之后。

**使用 Host 全局互斥。** 即使没有共享可变资源，无关提供方也会等待另一提供方的 I/O 或 owner 回调。

**保留外层租约时允许嵌套修改。** 等待该租约会自锁；穿透执行则允许外层 陈旧 快照存活到较新提交之后。因此回调内修改会被明确拒绝。

**取消时丢弃操作。** 已开始的写入可能在下一个事务之后才完成，因此取消不能在操作结算前释放所有权。

## 后果

源码回归使用合成服务和外部 Promise 屏障，保留真实并发请求，检查写入顺序、陈旧 修订号拒绝、失败释放、取消、引用共享和独立推进。不会用在自身持有的读取内等待嵌套修改的可重入 fixture（测试前置数据）模拟独立调用方。原有旧值覆盖场景在串行化修复前仍会由外部驱动复现失败。

这些租约协调同一 Host 共享的服务 owner。跨进程写入和绕过本 owner 的特权操作需要单独隔离；该机制不是分布式存储事务。安装态交互、真实提供方行为和完整覆盖率验收仍需要独立证据。
