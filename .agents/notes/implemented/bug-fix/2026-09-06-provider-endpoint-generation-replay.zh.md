# Agent Note: Provider 端点代际恢复

Status: implemented

[English](2026-09-06-provider-endpoint-generation-replay.md) | 中文

## 问题

凭据引用符合代际命名格式，并不能证明它属于下一个端点。豁免这种名称会让第二次端点切换在设置生效前覆盖上一个端点的凭据。仅删除豁免也不够：中断事务重试或恢复时，可能再次生成引用。

## 决策

现有 [LLM Remote 事务 owner](../../../../packages/llm/llm/src/provider-transaction.ts) 在端点改变且仍会复用当前引用时分配确定性的代际引用，不依据名称豁免。[日志恢复决策](2026-09-09-provider-journal-recovery.zh.md)把轮换扩展到已配置的同端点引用。原始输入绑定只包含秘密摘要，不包含秘密值；保留的旧计划与当前回执日志分别携带各自的绑定。

精确重试和持久化恢复检查 provider、命名空间、设置路径、输入绑定和日志摘要后，复用已记录计划。现有原子日志认领要求恢复请求仍拥有该事务：日志被替换或删除后，不能用旧恢复快照重新创建。新事务保留单独的已完成日志替换行为。精确重试允许修订号前进，但不允许操作或凭据改变。原有所有权、秘密路径、可写凭据源和激活检查仍然必需。

恢复入口把最初的日志快照经共享修改准入传递到该认领点，不能重新读取较新日志后，把旧恢复请求悄悄当作新事务。设置凭据、移除凭据和只改设置的恢复均使用同一个现有日志 owner。

原生 Settings 编辑器只从所选提供方声明的命名空间和路径读取 `apiKeyEnv`。配置缺失时，不回退到整个命名空间递归查找。新引用建议避开已配置的 API 密钥引用，已有明确引用保持不变。凭据状态加载、卡片草稿与自定义提供方创建共用同一解析器。这些建议不建立所有权：Host 仍拒绝跨提供方写入，凭据保存会在同一事务中包含其配置绑定。

原生 Models 表单在滚动视图中用非惰性堆栈承载可展开的提供方卡片。视口驱动的惰性布局不是草稿生命周期边界。macOS 26.5 的真实候选采样显示，更换新增提供方后反复执行 AttributeGraph 和惰性堆栈布局；源码布局检查不能替代原生滚动与空闲 CPU 验收。

原生设置刷新独立管理 Host 模型目录，不借用所选会话的元数据。每次刷新也会替换空目录，拒绝迟到结果，并刷新所选会话的可选模型。会话展示缓存保留历史，但不保存实时模型目录。具名凭据缺失时，该项不作为可用菜单选项。标准桌面为每个品牌显示一个菜单，去重模型 ID，同时保留其他模型各自的实际路由，不在普通 API 工作流中暴露 Token Plan 变体。展示过滤不会重写持久化配置或历史模型选择。

普通百炼预置复用已安装的 Qwen 协议实现和规范模型能力，同时保持普通端点和凭据所有权独立。请求使用文档规定的 `max_tokens` 字段，并通过有界最小生成验证精确认证，而不要求模型详情元数据端点。原生连接结果绑定被测提供方和模型，在设置刷新时失效。仅能证明地址可达的结果仍标记为未验证。

OpenAI 兼容模型详情返回 404 或 405 时，将验证交给现有的精确生成 owner；这既不表示成功，也不证明密钥无效。认证拒绝仍是错误，生成失败不能得到已验证结果。这样不会要求能正常处理模型请求的提供方必须实现可选元数据 API。

[执行所有权决策](2026-09-06-provider-transaction-execution-ownership.zh.md) 保护异步操作直到结算；单独的日志认领不能建立全生命周期所有权。引用代际与输入绑定仍是本文独立负责的决策。

## 考虑过的替代方案

**信任代际名称。** 引用可以是某个端点的当前代际，却不是下一个端点的代际，因此仍会提前覆盖。

**每次恢复都根据当前设置重新规范化。** 设置可能已切换，无法可靠重建原始请求和已认领代际；恢复必须使用持久化计划。

**新接入方式尚无配置时接受相邻提供方的凭据。** 展示分组不拥有凭据。整个命名空间的回退查找可能选中其他提供方的引用并导致保存被拒绝；放宽 Host 检查反而会允许凭据遭到破坏。

## 后果

提供方事务结算比较运行时路由是否存在与有效配置的预期，避免把删除误判为激活失败，同时保留继承配置的活动路由。自定义声明缺失时，只允许其精确保留的整项删除事务，且要求用户操作已满足、有效配置不存在、没有当前声明占用重叠路径。保留计划可完成凭据清理或返回回执，不能授权新修改。固定版本的 Responses 解析器将服务端报告型号保存在现有回放封装中；该报告不独立认证代理平台的模型。

原生调用详情仅从持久化请求 header 与助手消息来源投影允许展示的字段。缺失的服务端型号不能用请求别名填充；识别出的 pi-ai 回放响应提供可选的报告型号与响应 ID。该投影不序列化整个 header、回放签名或凭据。流吞吐率累加有计时依据的已完成调用区间，不跨越工具执行或重试等待。输出计数可能包含思考；首响应时间描述流事件，不代表正文出现。上述诊断既不独立认证远端型号，也不证明性能已经提升。

[日志恢复 owner](2026-09-09-provider-journal-recovery.zh.md)规范化完整的保留计划。缺少原状态证明不能授权重启后执行未提交编辑；不完整的请求绑定记录会被拒绝，而不是猜测。引用代际保护新的切换，但无法找回此前不安全写入已经覆盖的秘密。

[行为回归](../../../../packages/llm/llm/tests/provider-transaction.spec.ts)与[进程边界检查](../../../../packages/llm/llm/tests/provider-process.spec.ts)通过真实 Loader、文件存储 owner 与合成凭据，检查引用隔离、当前及旧日志、重试／恢复与所有权变化。它们不证明真实提供方流量隔离或安装态 GUI 稳定性。
