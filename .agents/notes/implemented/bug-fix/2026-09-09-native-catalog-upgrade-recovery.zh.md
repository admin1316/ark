# Agent Note: 目录升级保留原生修复入口

Status: implemented

[English](2026-09-09-native-catalog-upgrade-recovery.md) | 中文

## 问题

已安装模型目录可能移除模型或改变其协议，而用户设置仍引用旧条目。在注册 Settings 前拒绝这份配置，会使修复它所需的入口消失。如果 Harness 重建不完整的模型描述，适配器升级还可能丢失模型能力或历史推理元数据。

## 决策

现有 pi-ai 目录与 profile 管理层区分严格写入和延后校验的存储读取。存储读取只保留预期的 `PiAiCatalogError` 诊断，使独立有效的模型继续可用，并在同一目录中保留受影响提供方。同一个模型 id 重复时，该 id 的全部实例均失效。新增或改变的 profile 必须在持久化前通过严格校验；未改变的目录失效 profile 不阻塞独立提供方的编辑。标量校验和现有凭据隐藏规则保持强制，包括凭据值未改变的写入。

原生提供方 DTO 保留诊断，现有 Settings 卡片不依赖可用模型即可显示它。原生模型发现与提供方变更在发送请求前复用 HTTP URL 输入校验器。这些行为将[上游目录恢复](https://github.com/deepseek-ai/deepseek-harness/commit/e9b3f80f0b98bd68050bae30c092dd45a0b69697)接到原生消费方，不引入 Web 面板，也不迁移会话数据。

pi-ai 版本固定在包声明和锁文件中。穷尽式能力检查对新增字段进行分类；目录管理的回退模型元数据保留在模型描述中。自定义逐轮推理强度要求自适应思考，防止传输层静默使用默认强度。现有版本 2 的适配器回放封装记录可选的 `providerThinkingLevel`，保留提供方的历史选择，不改变会话格式版本 0，也不重写旧记录。

此决策部分取代[提供方声明决策](../architecture/2026-08-03-pi-ai-declared-provider-catalog.zh.md)中的启动目录校验行为。其路由身份、不可变快照和凭据归属规则仍然有效。[凭据投影决策](2026-09-09-provider-verification-and-header-ownership.zh.md)保持不变。

## 考虑过的替代方案

**从存储配置中移除失效 profile 或模型。** 发现与启动属于读取，不构成销毁用户设置的授权；静默移除条目还会丢失修复上下文。

**捕获全部配置异常。** 非预期缺陷和非法标量必须保持为失败；只有目录管理层的预期错误类才能成为修复诊断。

**用上游发行版替换整个应用。** 上游 Web 面板和会话格式迁移需要不同的消费方与验收，不能证明现有原生应用达到同等功能。

## 影响

失效模型在修复前仍不可用，其他提供方仍可独立编辑。任何设置写入前，明文凭据仍需显式迁移。真实 Loader 快照覆盖失效目录修复、私有端点请求预算和两轮推理回放。原生编解码测试覆盖修复诊断和在传输前拒绝非法 URL。这些检查不能证明真实账号可用性、GUI 同等功能、启动耗时或正式发布就绪。
