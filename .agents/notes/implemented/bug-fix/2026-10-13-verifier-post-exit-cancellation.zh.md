# Agent Note: 验证 helper 直接退出后的取消

Status: implemented

[English](2026-10-13-verifier-post-exit-cancellation.md) | 中文

## 问题

外部 Wiki 验证器收到有效签名响应、直接 helper 已退出时，受管后代进程仍可能运行。本地 subprocess runtime 会在直接结果结算后移除 spawn 的 abort 监听。此时没有传入信号的整组退出等待会忽略验证器时限和调用方取消，使验证在中断后继续挂起。

## 决策

验证器在 `child.done` 后的首次 `waitForExit` 中传入既有操作 controller 的信号。等待被中断时返回 false，既有 consumer 随后终止并等待受管进程树退出，再返回原有超时或取消错误。成功验证仍要求完整进程树退出和签名验证通过。

## 考虑过的替代方案

**直接退出后立即终止所有进程树。** 未采用，因为有限后代工作可以在既有时限内正常完成；不能仅凭直接退出判断签名结果是否可用。

**修改通用 subprocess 等待或另加时限。** 未采用，因为其他 consumer 持有长任务，而验证器已有经过校验的操作时限。应由该 consumer 传递信号，不改变共享语义，也不新增可调参数。

## 影响

操作等待可以被中断，没有新增权限、配置、wire 字段、签名字节或门槛。清理仍须等待受管进程树静止；逃逸后代或无法完成清理的不透明 provider 不在此保证范围内。不会立即把存活后代判为 orphan：有限工作可以完成，否则由既有时限触发终止和超时拒绝。

## 验证

所属 adapter 测试执行真实 Node helper：它返回签名结果并退出，同时仍有可以独立观察到的存活子进程。超时和取消会在受管清理后拒绝；有限后代自然退出时保留经过验证的结果。测试另有失败清理 owner，不把它的清理算作验证器成功清理。这些探针只覆盖实际执行的本地 runtime，不代表原生激活或完整平台矩阵通过。
