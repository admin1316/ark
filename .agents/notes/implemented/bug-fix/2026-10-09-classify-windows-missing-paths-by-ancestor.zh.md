# Agent Note: 按最近的现存祖先判断 Windows 缺失路径

Status: implemented

[English](2026-10-09-classify-windows-missing-paths-by-ancestor.md) | 中文

## 问题

当路径穿过普通文件时，Windows 可能返回 `ENOENT`，而 POSIX 系统会返回 `ENOTDIR`。把所有 `ENOENT` 都当成可忽略的文件缺失，会让 Wiki 读取和恢复流程把不安全或格式错误的路径隐藏成普通缺失。

## 决策

文件系统回退逻辑持有目标路径时，共享的缺失路径检查会从目标的父级向上查找最近的现存条目。只有该条目是普通目录时才把 `ENOENT` 视为缺失；如果它是文件、符号链接，或检查本身遇到其他错误，就保留原始失败。没有路径上下文的调用方仍只检查错误码。Wiki 文件系统和治理逻辑会传入具体目标路径，测试分别覆盖“文件下的子路径”和“普通目录下的缺失子路径”。被文件阻断的子路径必须保留宿主原生错误（POSIX 为 `ENOTDIR`，Windows 为 `ENOENT`），不得当成缺失的 Wiki 根目录。

## 考虑过的替代方案

**把所有 `ENOENT` 都当成缺失。** 否决：在 Windows 上，这会混淆普通缺失与祖先为普通文件的错误路径，导致可选读取或恢复掩盖格式错误状态。

**按操作系统分支处理或接受 Windows 特有错误。** 否决：这会把宿主差异散布到每个调用点，并削弱共享的失败关闭约束，而不是检查导致错误的文件系统状态。

**跳过受影响的 Windows 测试。** 否决：支持平台矩阵必须继续验证相同的安全约束；确定性 fixture 覆盖行为，原生 Windows CI 验证实际平台错误映射。

## 后果

真实目录下的可选缺失读取和清理仍可正常处理；文件或链接下的失败则会在各支持平台上一致传播。额外祖先检查只在 `ENOENT` 后执行，可能进行少量同步 `lstat` 调用。Windows fixture 不再依赖宿主无法提供的 POSIX 权限位、路径分隔符、shell 名称或权限更改。
