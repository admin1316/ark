# Agent Note: 稳定的 profile 组合包解析

Status: implemented

[English](2026-09-13-stable-profile-bundle-resolution.md) | 中文

## 问题

另一进程原子替换后备符号链接时，profile 解析器可能把已安装的组合包报告为缺失。在 macOS 上，穿过被替换链接的路径查询可能返回 `EINVAL`；`existsSync` 会将此错误折叠为 `false`。目录项的原子发布并不使后续多级路径查询成为不可分割的操作。

## 决策

现有 `packageDirFromAnchor` 使用 Node 原生 `realpathSync`，先确定包目录，再检查其 manifest。调用方获得解析后的目录，后续读取因此使用同一目标。优先查找安装目录的顺序保持不变，exports 未公开 `./package.json` 的包仍受支持。路径缺失时继续查找，其他解析错误向上传递。写入方保留暂存符号链接替换机制。

## 考虑过的替代方案

**在并发测试中忽略失败的存在性检查。** 这会掩盖已复现的生产组合包解析故障。

**手工读取符号链接。** 并发替换也使 `readlink` 返回 `EINVAL`；原生路径解析避免再维护一套遍历算法。

## 后果

返回路径采用文件系统规范形式，包括 macOS 的 `/private/var`。独立进程在反复替换期间调用生产解析器并读取包身份，任何失败仍使断言失败。绝对、相对、悬空和循环链接均有明确检查。这验证文件系统解析，不代表原生 App 验收，也不保证选中的安装目录本身被删除后仍可继续读取。
