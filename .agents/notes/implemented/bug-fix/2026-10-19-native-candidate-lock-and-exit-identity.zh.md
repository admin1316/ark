# Agent Note: 拒绝不完整的离线锁并保留退出身份校验

Status: implemented

[English](2026-10-19-native-candidate-lock-and-exit-identity.md) | 中文

## 问题

pnpm 11.7 在离线推导锁文件时，可能报告某个可选依赖的 `resolution_failure` 并省略其后代，却仍成功退出。在 Ark 的 `sharp` 依赖图中，即使普通元数据仍在缓存中，缺少 `@img/sharp-wasm32` 和 `@emnapi/runtime` 的完整元数据缓存也会产生不完整的锁。收据正确地拒绝了缺失的根锁定解析结果。补回这些完整元数据后，同一离线命令便会逐字节重现完整的在线锁，因此 CPU 支持度不能解释该遗漏。

父进程死亡与 `SIGTERM` 竞态测试可能在 macOS 已将保留进程的 argv 替换为 `(node)`、而 `ps` 尚未报告僵尸状态或移除该行时观察到它。立即拒绝该观察会使正常退出导致测试失败；把任意 argv 丢失都当作退出，或向身份已变化的 PID 发信号，则会削弱进程所有权校验。

## 决策

[运行时计划](../../../../integrations/jiuzhang/src/runtime-plan.mjs) 保留根锁定的外部依赖图，包括外平台可选解析结果。[打包所有者](../../../../integrations/jiuzhang/src/pack-runtime.mjs) 使用 `--reporter=ndjson` 推导锁文件，并将输出交给 [`assertArkOfflineLockResolution`](../../../../integrations/jiuzhang/src/runtime-closure.mjs)。即使 pnpm 以零退出，该辅助函数也会拒绝因 `resolution_failure` 而跳过的可选依赖。正常的平台跳过仍被允许。在线完整元数据缓存准备与离线打包相互独立；缓存不完整不能改变打包所接受的依赖图。

[运行时锁校验器](../../../../integrations/jiuzhang/src/runtime-closure.mjs) 由安装前校验与最终收据校验共用。打包在冻结离线安装前，先按计划中的精确解析结果、完整性值和依赖边检查推导出的锁。最终收据保留同样的严格校验，独立于包管理器的诊断信息。

[进程身份辅助函数](../../../../integrations/jiuzhang/tests/helpers/process-liveness.mjs) 将启动时间相同的僵尸进程视为已退出，不向它发信号。对于启动时间相同且与括号包裹的可执行文件名精确匹配的占位符，异步辅助函数最多观察十次，间隔 10 ms。该占位符从不授权发送信号。只有新鲜观察行与保留的启动时间、可执行文件和完整 argv 全部匹配时才授权发送信号；行不存在或启动时间相同的僵尸状态则确认退出。其他身份变化立即失败，持续存在的占位符则在有界观察结束后失败。

[生命周期测试](../../../../integrations/jiuzhang/tests/lifecycle.test.mjs) 将启动时间相同的非僵尸进程保守地视为存活，即使 argv 不可用。这能避免清理断言在模糊区间内误报成功。原始失败运行没有记录 `ps` 状态，因此无法还原其精确状态；本机复现独立证实了从睡眠状态占位符到进程行消失的转换。

## 考虑过的替代方案

**裁去外平台可选后代，或放宽收据校验。** 元数据缺失可在不依赖目标支持度的情况下复现截断的依赖图。接受该图会把离线解析失败变为被允许的依赖变化，并削弱根锁的权威性。

**信任 pnpm 的退出码，或等到最终收据校验。** 零退出码不会暴露可选解析失败，仅在最后校验则会在安装和 manifest（元数据清单）工作之后才发现问题。结构化诊断与精确的安装前校验能在推导锁文件的所有者处拒绝不完整结果。

**允许打包过程联网恢复。** 这会将运行时组装与在线解析耦合，并违反其离线安装策略。缓存准备单独提供元数据；打包仍要求完整的根锁定结果。

**忽略进程身份错误，或仅按 PID 发信号。** 两者都可能掩盖存活的遗留进程，或向复用的进程发信号。有界复察仅处理已识别的退出占位符，并保留每次发送信号前的严格身份校验。

## 后果

[运行时计划测试](../../../../integrations/jiuzhang/tests/runtime-plan.test.mjs) 固定了外平台 WASM 链的保留、单一离线锁推导与安装所有者，以及安装前校验。[运行时闭包测试](../../../../integrations/jiuzhang/tests/runtime-closure.test.mjs) 固定了无需已安装内容的严格锁校验、对可选解析失败和非法报告输出的拒绝，以及对正常平台跳过的接受。生命周期回归覆盖新鲜匹配行、PID 复用、argv 与可执行文件漂移、持续模糊状态、保守存活判断，以及由暂停父进程保持未回收状态的真实子进程。启动器关闭协议保持不变；竞态测试的观察与信号授权更加精确。

源码检查确立了这些机制。正式运行时打包成功、候选安装态校验与原生交互验收仍是独立证据；仅源码测试不能确立发布就绪，也不能证明与旧应用一致。
