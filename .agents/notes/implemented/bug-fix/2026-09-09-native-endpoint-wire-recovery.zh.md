# Agent Note: 恢复原生端点参数与持久子会话收据

Status: implemented

[English](2026-09-09-native-endpoint-wire-recovery.md) | 中文

## 问题

重建源码可能发布了 Remote 名称，却接受与原生客户端不同的参数或返回不同的值。仅重命名端点不能修复这种错位。子会话提示的首次确认丢失后，重试也可能再次插入消息；无关的落盘监听器不能证明存储所有者已经持久化消息。

## 决策

预设与 subagent 服务绑定单数 `agentPreset` 和 `subagent` 协议命名空间，不改变 Context 服务键。预设选择复用串行化的空白会话切换，复制和选择返回预设 id，原生打开器根据 id 解析用户拥有的目录。读取、复制、选择和打开器失败不会返回原始基础设施诊断。

Ark 的受管 profile 使用现有的 `includeShippedRoot: false` 选项，防止通用内置预设排在启动器的原生预设根之前并将其覆盖。共享的原生 standard/code/minimal 定义拥有各自工具目录，包括团队、调度和一次性 fork 策略。通用 CLI 定义保持完整，供选择它们的部署使用。

LLM 所有者提供原生提供方与模型目录封装，以及请求对象形式的模型发现接口。提供方失败相互隔离，一次性密钥不会返回，取消保持独立。这些读取操作并未实现缺失的提供方配置事务。

现有继续执行管理器在子会话锁内拥有持久提示收据。它校验调用方 UUID 和直接父身份，在异步工作前快照内容，并且只查找子会话自己的日志后缀。精确重试返回原消息 id，冲突复用会被拒绝。消息接收后等待 Session 落盘及实际持久化所有者的物化屏障。较晚的取消不打断该工作，失败也不撤回已接收消息。没有第二套队列或收据数据库。这扩展了[继续执行设计](../feature/2026-07-28-continuable-subagent-conversations.zh.md)，同时保留其首次启动确认和驻留规则。

子会话历史先核对目录。Session 历史所有者在渲染有界分页前，对实际来源 header 检查预期父身份，阻止期间替换来源后取得其他父会话历史。

## 考虑过的替代方案

**只修改路由名称。** 原生模型发现、预设复制和提示收据还要求不同的参数与响应封装。

**保留进程内重试记录。** 它们会在重启后消失，并在现有收件箱与事件日志之外增加第二个持久化真源。

**把任意成功落盘回调当作持久性证明。** 选定的持久化所有者也必须完成自己的屏障；通知观察者不是存储。

## 后果

真实 Loader 测试与无密钥快照覆盖并发和冷状态重复提示、存储失败、较晚取消及模型轮次数。预设 Loader 测试覆盖复制、读取、删除和原生交接授权。生成编解码器的冒烟检查覆盖原生形状的输入与回复。提供方配置事务、穷尽覆盖率、组装应用验证与正式晋级仍是独立且未闭合的要求。
