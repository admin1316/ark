# Agent Note: GUI 测试体系——协议、状态与原生展示

Status: implemented

[English](2026-07-20-gui-testing-system.md) | 中文

## 问题

Ark 跨越 Host 领域操作、认证 API 载体、客户端状态机与 AppKit/SwiftUI 布局。单一端到端检查无法定位全部故障，快速 fixture 测试也不能证明真实载体行为或原生响应性。[仓库测试策略](../../../../docs/testing.zh.md) 负责通用覆盖与真实组合规则；本记录负责 GUI 证据的分工。

## 决策

测试遵循当前架构中可以独立观察的边界。[Web UI 退役](../simplification/2026-08-29-retire-generic-web-ui.zh.md) 移除了浏览器组件与 Client loader 检查，但没有移除分别验证协议、状态和完整展示的要求。

| 层级 | 属主 | 证据 |
| --- | --- | --- |
| Host 与线路 | [Host Connection](../../../../packages/host/connection/tests)、[API gateway](../../../../packages/api/gateway/tests)、领域 Remote 测试 | 实际分派、序列化、授权、取消与失败行为。 |
| 原生状态与协议 | [Native 约定测试](../../../../integrations/jiuzhang/native/Tests/JiuzhangShellCoreTests) | 可控事件历史、分页、会话选择、延迟请求、草稿所有权与投影结果。 |
| 完整展示 | 原生 App 及其打包 sidecar | 真实窗口交互、请求传输、滚动与输入行为，以及有界 CPU 测量。 |

状态测试使用“事件序列输入、快照输出”的路径，只控制不确定输入：延迟响应、时钟与外部服务。纯投影函数直接测试。交互回归运行实际属主视图与控制器组合，不用待测行为的伪实现替换昂贵依赖。

每层拥有自己的断言。底层固定线路与状态语义，上层固定可见行为及真实属主之间的集成。录制 fixture 有助于确定性状态转换，但不能认证网络生命周期、授权或系统布局。在能够覆盖这些边界时，仍需无密钥真实组合；有凭据的提供方检查证明另一条边界。

现有[历史窗口约定](../../../../integrations/jiuzhang/native/Tests/JiuzhangShellCoreTests/ArkHistoryWindowContractChecks.swift) 在带硬截止的子进程中隔离历史、工作台宽度与输入状态的组合转换，捕获纯投影断言看不到的主线程布局停滞。有界历史窗口仍属于约定；布局修改不能悄然渲染全部保留历史。

## 验证纪律

每个修复的缺陷都需要在实际属主处有断言。载体修改需要真实载体测试；原生布局或手势修改需要原生交互证据。构建、签名、fixture 或 Host 测试单独通过，都不能使已安装 App 达到发布条件。结果应保留退出码、进程身份、状态与测量时长。

预期行为改变时，应一起核对实现、所属决策与测试。不要遗留失败断言、增加超时来掩盖挂起，或用模拟成功替换真实路径。使用当前[开发命令](../../../../docs/development.zh.md)，不在本决策中维护第二份命令清单。

## 考虑过的替代方案

**所有内容只用端到端测试。**这会为低成本状态检查重复启动应用，也难以控制事件竞争；定向状态测试可以确定性隔离这些场景。

**只用隔离状态或 fixture 测试。**它们不能证明被绕过的传输与系统 UI 机制，因此确定性状态检查与真实组合证据都必不可少。

**把真实时钟的演示作为通用伪对象。**演示时序与可控并发测试的用途不同；强制复用会让测试结果依赖演示调度。

**把浏览器输出当作原生验收。**原生产品有不同的布局、焦点、生命周期与资源行为。已移除的浏览器检查不能替代实际 AppKit/SwiftUI 证据。

## 影响

无需为每个纯状态断言支付完整 App 成本，即可定位失败。接受的成本是多层互补证据及真实原生验收步骤；底层通过从不意味着用户可见 App 已通过。
