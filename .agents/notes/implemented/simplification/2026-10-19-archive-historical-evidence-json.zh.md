# Agent Note: 保留当前证据并归档历史 JSON

Status: implemented

[English](2026-10-19-archive-historical-evidence-json.md) | 中文

## 问题

迁移分支把带日期的候选结果和已被替代的结果 JSON 与源码及当前验收输入放在一起。保留全部历史输出会让工作树变得嘈杂，掩盖当前检查真正消费的证据，也会让基准运行回执以独立文件持续堆积。

## 决策

仓库保留当前验收清单，以及保留的聚合基准记录所引用的七份运行回执。其余 61 个历史结果 JSON 已从工作树移除。`scripts/rust-migration/historical-evidence-index.tsv` 记录每个移除路径、字节数、行数和 SHA-256。本地隔离归档保留精确字节，用于回滚和取证重放；该归档有意放在仓库之外。面向人的链接指向索引，而追加式 progress 和 security 记录继续保留原始历史路径及哈希对。新的基准运行回执在聚合进总记录之前会被忽略，避免静默积累。

## 考虑过的替代方案

**继续把所有历史结果保留在 Git 中。** 不予采纳，因为当前验收输入已经定义一次运行所需的证据，带日期的替代输出会增加检出噪声，让生成物看起来像源码。

**不做归档直接删除文件。** 不予采纳，因为旧结果仍可用于取证对比，其路径哈希也属于保留的清理证据。

**把原始归档提交到 GitHub。** 不予采纳，因为这会以另一种形式保留相同的生成物体积，使日常源码检出仍携带当前代码不会消费的证据。

## 后果

干净检出仍包含当前源码、测试、验收产物和聚合基准回执。历史原始结果需要通过本地隔离归档和 SHA-256 索引恢复；仓库不再把这些结果呈现为活动输入。未来基准运行不能在没有显式聚合步骤的情况下静默新增一个 JSON 文件。
