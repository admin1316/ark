# Agent Note: 将 inbox 消费与步骤输入提交为一个原子组

Status: implemented

[English](2026-10-20-atomic-inbox-input-commit.md) | 中文

## 问题

已接受的 inbox 消息可能在异步提示词准备完成之前，就从持久待处理工作中消失。在这个区间中断进程，会使待处理输入与 `user/message` 记录同时缺失。`finally` 中重新入队可以处理协作式失败，却无法修复被杀死的进程。同步连续执行普通追加也会留下部分持久前缀，因为写入可能失败，存储恢复也会从撕裂的压缩帧中抢救完整记录。

## 决策

循环预览所选 inbox 消息，而不删除它们。如果选择在 `agent/pre-step` 之前改变，提示词组装可以重新开始；需等待的 pre-step 决策只运行一次。消费之前，inbox 验证确切的所选消息标识与位置仍然有效。不相关的尾部新增消息保持独立；决策期间编辑已选消息会结束本次尝试，不重跑可能有副作用的钩子。带 `keepInbox` 的取消与准备失败保留待处理输入。显式拒绝消费预览，并关闭 blocked 轮次。

pre-step 监听器可以在输入仍待处理时追加仅日志事实。因此，一次性子代理的 `subagent/descriptor` 位于 inbox 消费之前；它标识已建立的子代理，而不新增模型可见消息。针对请求 checkpoint 的存储失败夹具在步骤进入后武装，与更早的准备 checkpoint 分离。

步骤进入通过 `Session.appendAtomic` 一起提交规范化的 inbox 删除 splice、`step/start` 与每条最终 `user/message`。会话在发布任何成员之前，为整组创建快照并验证，包括临时表层状态转换。它安装完整组，发出一次 `session/committed(session, events, true)` 通知，然后逐条发出 `session/event`。普通追加通过同一 committed 通知发出一个事件与 `false`。持久化只消费 committed 通知；UI 与投影消费方保留逐事件通知。这样存储分组与逻辑事件分类分离，且不复制事件载荷。

持久化队列通过规范序列号，在批处理与重试期间保留组坐标。JSONL 将每组写为一条版本 `1` 的 `atomic-events` 记录，必需的物理 `seq` 等于首成员序号；压缩时每条原子记录独占一帧。解码器在暴露成员之前验证整条记录，因此纯文本按字节截断与 Zstandard 前缀抢救都不会只接纳其中的 inbox 删除。完整原子记录中的成员、护栏或序号无效时，即使尚无 `turn/end`，也会作为损坏拒绝。撕裂帧恢复重新编码抢救记录时保留已接受的组坐标，使修复期间再次中断也不会破坏原子性。护栏与帧分离共同使 Ark 3.1.2 读取方保留完整的未知记录，并在修复之前拒绝解释。没有护栏时，尾部不受支持的记录会像未完成追加；没有帧分离时，后续单事件的序号缺口可能丢弃包含护栏的整帧。SQLite 在一个数据库事务中追加整批内容。JavaScript 调用栈与压缩帧都不能替代经过整体验证的完整记录。

[单一 pre-step 决策](2026-07-31-claimed-pre-step-inbox-lifecycle.zh.md)继续拥有单一 waterfall（瀑布式事件）、`MessageId` 寻址与最小实时通知的约定；本决策取代它准备前领取的时序。[分片打包决策](2026-07-26-packed-chunk-rows-by-default.zh.md)继续拥有普通分片行。原子组使用既有 `SessionEvent` 值并保留逻辑格式版本；其物理记录有自己的版本。旧应用无法消费这个封装。严格离线导出把完整副本产物展开为单事件 JSONL，供隔离回滚配置使用，并拒绝损坏或不完整输入。

## 曾考虑的替代方案

**在 `finally` 中恢复已领取消息。** 进程终止后无法运行该逻辑，持久删除早于输入的区间依然存在。

**领取前 flush，再逐条追加普通事件。** 这能保住更早的写入，却不能使之后的删除与输入不可分割。删除后 flush 反而可能持久暴露需要保护的缺口。

**队列变化就重放准备。** pre-step 监听器可能执行副作用。循环接受独立的尾部新增消息，但已选区段改变时会失败，而不自动重复监听器。

**将每个压缩追加帧视为原子单元。** 恢复有意从撕裂帧中抢救完整记录。在这个策略下，只有经过整体验证的物理记录才能保住逻辑组。

**再保存一份持久输入副本。** 既有 inbox 与用户消息事件已经描述待处理及已进入的输入。物理分组封装保住它们的关系，而不增加另一个真源或新的模型可见内容。

## 验证

会话与 inbox 测试验证整组校验、单次 committed 通知、观察方看不到部分组、提交前取消、已选消息编辑与延后的观察方取消。agent-instructions 测试覆盖已选工作区上下文，保证准备期间不删除预览。JSONL 测试在纯文本每个字节处截断原子记录，并抢救不完整 Zstandard 帧；两种编码都拒绝损坏的完整组且不改变源文件字节，即便只有一个成员，护栏也必须与首成员一致。修复测试恢复校验和撕裂的组，并在重新写入字节的每个位置截断，要求整组成员全部恢复或全部不恢复。SQLite 测试注入后续插入失败，并要求事务回滚。导出测试比较两种编码的精确逻辑事件，并拒绝不完整输入。已安装 Ark 3.1.2 持久化库在纯文本／压缩、单／多成员、位于尾部／后跟单事件的合成场景中，均拒绝带护栏的产物，且不改变文件字节。组装后的 headless `input-atomic` 无密钥快照同时检查模型可见记录与实际持久化输入组及护栏。

TypeScript SDK 快照为父运行时与通过 SDK 启动的子运行时显式选择源码 CLI，并在逻辑断言之前解码物理组。其严格日志固定 descriptor 早于消费的顺序。打包后的 Python advanced 与 restart 快照保留真实原子存储记录；回放展开这些记录，而不放宽载荷或通知比较。

## 后果

已接受输入的转换拥有一个内存校验边界与一个持久存储边界。钩子观察仍待处理的输入，必须返回当前步骤改写，而不是自行删除已选批次。逐事件监听器观察到的会话已经安装完整组。该设计不使外部工具副作用事务化，不保证 flush 成功之前已持久化，也不建立严格内存上限。回滚需要独立导出的配置目录，因为旧读取方不理解新的物理封装。
