# Agent Note: 原生命令持久回执

Status: implemented

[English](2026-10-20-durable-native-command-receipts.md) | 中文

## 问题

原生命令可能在响应到达应用之前已经改变领域状态。响应断线后重复运行处理器可能再次执行变更；忘记被中断的命令，也无法判断其副作用是否发生。仅靠请求生命周期不能在应用或 Host 重启后继续拥有这种不确定性。

## 决策

Host 暴露 `session/command`，接收调用方已持久保存的调用身份、确切命令行和有序图片，并在解析 Agent 前读取活跃或冷会话回执。`CommandRuntime` 拥有执行及基于 `command/run`、`command/done` 的回执投影，不创建第二份 JSON 账本。可选调用元数据保持 `SESSION_FORMAT_VERSION` 为 `0`，并允许读取没有重试身份的记录。

新调用在进入处理器之前确认开始记录落盘，在报告 `completed` 之前确认终态记录落盘。输入摘要把身份绑定到确切命令行及有序图片内容。同一身份观察 `running` 或回放原来的成功、错误终态；不同内容发生冲突。已经准入却没有确认结果的执行返回 `unknown`，保留身份且不重新进入处理器。同一会话最多拥有一个活跃命令，不在它后面排队接受另一次调用。

Host 活动信号独立于 HTTP 响应观察而拥有取消。进入处理器后，执行所有权持续到处理器实际结算，包括不配合取消的处理器。退出会等待实际结算。Host 确认可以退出或已经观察到后端退出后，原生清理可以取消并等待响应观察者结算，同时不确认清除其 journal。

### 原生确认

一个原生提交 owner 复用现有私有 inflight journal。composer 命令在成功确认回执之前保留捕获的提交身份、草稿和附件引用。已确认的 composer 错误保留草稿。独立按钮与菜单操作只在错误已经显示后退役相应的已完成记录；后续明确点击使用新身份。两种路径都不会把 `running`、`unknown` 或传输失败转成新调用。

新会话权限前置命令根据捕获的父提交及确切权限命令推导独立身份，因此即使本地确认丢失，重试仍观察同一个前置调用。明确权限选择成功后，通过持久的比较并保存清除相应草稿被冻结的前置条件，同时保留主提交身份。

[注册决策](../feature/2026-07-19-plugin-command-registration.zh.md)仍拥有插件作用域及人类／模型平面的分离；其分派与恢复限制在此被部分取代。[图片信封决策](../feature/2026-08-17-command-image-attachment-envelope.zh.md)仍拥有生产方声明与完整信封准入。同进程 `executeLocal` 没有 Remote 路由，也不提供持久重试保证。

## 考虑过的替代方案

**每次重试使用新身份**会丢失与已执行副作用的关系，无法区分响应丢失与新意图。

**独立命令 JSON 账本**会重复权威会话日志，并引入另一个崩溃一致性边界。投影改为保存指向原有记录的坐标。

**响应被取消就代表执行已经停止**会为不合作的处理器制造错误终态。完成边界仍是处理器实际结算。

## 后果

重试保留同一个已准入调用，无须模型配置或再次调用处理器即可恢复已记录结果。未知结果可能需要检查被操作的领域；自动回放无法修复未记录的外部副作用。此约定不保证跨外部系统的 exactly-once，用户明确发起的新调用仍可能再次执行操作。

## 验证

真实 Loader／Agent／JSONL 命令组合固定了合成文件副作用前的持久准入、并发与冷重试、中断执行、错误回放以及明确新意图。原生契约覆盖原身份、草稿保留、权限覆盖及响应清理。两个 SDK 均通过真实 stdio 客户端回放同一份合成命令元数据。
