# Agent Note: 顶层会话的自动摘要准入

Status: implemented

[English](2026-10-12-session-summary-admission.md) | 中文

## Problem

Knowledge Wiki host 会在 agent 销毁时绕过模型文件工具直接写入自动 Candidate。委派 agent 与父会话共享工作区，也已将发现发送到父会话对话中。把每次销毁都视为独立摘要的所有者，会在委派读取任务期间生成重复页面和文件。会话来源关系本身不代表文件权限，approval 模式也不能替代文件策略。

## Decision

写入方使用可选 session-query 服务的完整快照与现有 sandbox-policy 事件折叠，只准入与请求匹配的顶层会话身份、未设置 origin 和 parent 来源关系、为零或未设置的 delegation depth，以及明确记录的可写模式。既有的非主工作区和对话长度检查仍然适用。缺少文件策略时跳过自动摘要，不借用未记录在快照中的部署默认值。父会话仍可通过对话与 settlement notice 获取子会话的结果。

异步摘要阶段完成后，写入方重新读取准入状态，在落盘前比较 cwd、模式、事件数量与提取的对话。事件数量也能拒绝超出提取长度上限后追加的新输入。操作现有的 controller 会在取消后拒绝发布。读取与写入错误仍限制在尽力而为的销毁处理路径内。Candidate 格式、评审治理、sandbox 执行、模型路由和晋级要求保持不变。

## Alternatives considered

- 只过滤销毁 listener：否决，因为直接调用摘要的路径会绕过准入。
- 关闭自动摘要：否决，因为顶层可写对话仍拥有这一受支持行为。
- 根据 `approval=never`、来源关系或 prompt 文字推断写入权限：否决，因为它们不能提供日志中的文件策略或结构化的逐文件授权。
- 为每个子会话单独汇总：否决，因为父会话已经收到发现，并拥有整个任务上下文。

## Consequences

委派、只读、未记录策略和输入已变化的摘要不能单独发布自动 Candidate。既有顶层可写摘要仍会创建、合并相同的页面与评审记录。未明确记录模式的旧会话不再符合自动摘要条件；显式摄取与既有受治理 Wiki 操作仍分别执行其自身授权。

这是一项同进程写入前复查，不是原子锁或多文件回滚。顶层可写策略只提供粗粒度准入，不是逐文件任务授权：该摘要路径不执行任意自然语言文件白名单。源码拒绝测试与真实 Loader 销毁组合测试验证了这一决策，但不能证明独立验证器的密钥保护、知识复用、安装候选验收或实测性能提升。
