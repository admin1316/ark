# Ark 长会话修复与干净正式交付

本任务从源码与运行实物出发执行 P0–P8。唯一状态台账为 [long-session-release-state.json](long-session-release-state.json)，只有主代理可以更新阶段、生成共享产物、操作 App、晋升和删除。

## 最终要求

- 唯一正式 App 为 `/Users/hui/ark/Ark.app`；测试身份和版本独立，候选固定为 `/Users/hui/ark-test/candidate/Ark.app`，完成后删除。
- 修复长会话 CPU、输入滚动卡顿、历史可达性和消息完整性；进行局部根因重构，保留 Native UI、取消、持久化和权限边界。
- 保留唯一主源码、必要回归测试、精简技术结论、模型配置与凭证、独立知识库、用户项目和未保存文件草稿。
- 正式安装验收通过后清空全部 Ark 真实与测试对话，不保留任务制作的对话恢复副本；不得把源码测试样例或 Workbench 文件草稿当作对话垃圾。
- 完成历史目录的源码沉淀和依赖解除后再逐项清理；未识别对象、仍被使用对象、未保留的独有源码不得删除。

## 分工与互斥

主代理负责 P0/P1、共享接口与配置、锁文件、生成 lib、构建、所有进程和 UI 操作、发布、清空、垃圾清理及状态台账。原生代理独占聊天状态、feed、阅读窗口、滚动、Markdown 和图片的实现与测试；后端代理独占 Session、TokenMeter、SessionProjection 的实现与测试；独立审查代理只读复核。Ark 内部协查只使用独立诊断会话和只读资料。

共享文件包括 Package.swift、Package.resolved、Info.plist、AppDelegate、ArkL10n、测试主入口、根配置、运行 profile、构建安装脚本和所有生成物，均由主代理修改。终端/Workbench 既有修改保持冻结，只有复现问题并转交文件所有权后才允许修改。模块不得并发写同一文件；构建期间冻结输入；真实性能测试期间停止编译与其他压测。

## P4 的具体检查

共享产物构建前先冻结源码并退出引用主树的候选后端。完整 Host 检查使用 `NODE_OPTIONS=--max-old-space-size=4096 pnpm run build:lib:host`，编译整个 `tsconfig.host.json` 后再打包；保留严格类型检查。Native 运行依赖使用现有 `node integrations/jiuzhang/src/build-native.mjs` 生成，并记录源码与产物指纹。

原生回归使用 `swift run --package-path integrations/jiuzhang/native --skip-update JiuzhangShellContractTests`，所有注册组必须执行且退出码为零。后端按实际修改的 Session、TokenMeter、Projection、Query、Host、Compaction、格式转换与发布身份模块运行现有行为测试；新增线协议同步现有生成器与装配回归。文档执行已改双语配对、链接及 Agent Note 格式检查；全仓遗留失败逐项记录归属与处置，不能把定向通过写成全仓通过。

P4 收据逐条记录实际命令、退出码、源码指纹、诊断和未解决项。构建、单元测试及有限探针通过只完成各自检查；P5 的真实 Native 性能和功能验收必须单独完成。

## 验收

关键行为包括超过 50,000 事件后真实加载旧页、窗口外跳转、流式期间阅读旧历史、迟到解析与会话切换、最终输出与完整复制导出、不可变事件快照、投影晚注册和恢复、上下文压缩、取消、重连、中文输入、终端往返与正常退出。

输入/按钮响应 P95 不超过 100ms，滚动帧间隔 P95 不超过 33ms，无超过 1s 的主线程停顿。稳定空闲 60s 的 App 与所属后端合计 CPU 均值不超过 2%；单进程高于 80% 不连续超过 5s。关键对照三次，并完成 60 分钟混合操作观察；不以增加可见输出延迟替代降低计算成本。记录启动、恢复、准备数据、流式、阅读与空闲的全部阶段。

清理台账逐项记录绝对路径和真实路径、归属与用途、指纹、独有内容去向、依赖者、前置验收、执行状态和删除后验证；密钥、连接令牌和对话正文不得进入永久回执。
